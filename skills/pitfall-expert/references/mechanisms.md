# 机制详解（M1–M12）

> SKILL.md 是速查表，本文件是完整规则。每个机制附来源（综述/案例编号，可追溯至 docs/02 与 cases/）。

## M1 用户约束画像先行

**规则**：预检维度清单的第一来源是用户真实约束，第二来源才是通用清单。任何「够用/兼容/匹配」类判断前，先生成「用户约束画像」：读得到的用户环境数据逐项列出——历史用量、上下文水位、既有配置、设备/网络/权限约束、使用路径（CLI 还是 API、主力会话多长）；读不到的字段显式标注「画像缺失」，此时容量类结论强制降级为待验证假设。**最小化采集（v0.6.2）**：画像只取决策相关的聚合值（如「月耗 $100–200」），薪资/健康/证件号等敏感原文一律不进报告——报告会被粘贴、转发，画像缺失上报不等于授权深挖上下文。

- **来源**：案例 D2（验证清单按通用模板，漏查 context_budget；用户 75.4% token 在超限会话）、D3（两天样本推「够用」）。
- **为什么有效**：通用清单查「大家都怕的坑」，画像推导查「这个用户会撞上的坑」。232K 上下文对一般用户不是坑，对主力会话 26–41 万 token 的用户是致命坑。
- **实操**：接入类任务必检项 = 用户历史上下文水位、月耗、并发模式；可从本地账本/会话记录读取，读不到就先问，问不到就降级。

## M2 量纲审计前置

**规则**：任何比较/排序/推荐类结论，先完成「计量口径审计」：所有比较对象的计量基准（计价口径、汇率、单位、含税/手续费、有效期、版本号）换算一致后才允许输出排序，审计过程附在报告。

- 价格/额度类必检字段：计价基准（闲时/高峰/混合）、缓存计价、隐藏费用、过期规则、窗口规则、退款条件。
- **来源**：案例 D4（一家按高峰价扣、一家按闲时价记——「两家的 $1 不是同一种美元」，初版排序整体反转）。
- **反面示例**：「A 家 $120 > B 家 $100，所以 A 划算」——未审口径前这个排序没有任何意义。

## M3 信源分级绑定动作

**规则**：每条外部信息入库标注等级——`A 官方一手`（官网/文档/API 实测）/ `B 权威二手`（主流媒体/论文转述）/ `C 社媒传言`（短视频/论坛/道听途说）。**C 级只能触发「核实任务」，不得触发「分析任务」**：基于 C 级信息的分析在完成 A 级核验前不得进结论区，整体放 ❓ 区。**A 级源正确性衰减（v0.6.2）**：A 级是静态权威，不防「曾经正确、现已过时」——文档滞后于版本是常态。唯一证据为官方文档的 ✅ 必须附版本核对行（文档所述版本 vs 实际部署版本）；文档与实测冲突时以实测为准（与 L3 信任序一致——M3 管信源权威轴，L3 管验证方式轴，两轴正交不矛盾）。

- **来源**：案例 D5（抖音「限时三天」未核实即展开完整分析，官方页实为月度提升，整层分析作废）。
- **要点**：标注可信度 ≠ 免责完成。分级必须绑定动作，否则标注只是装饰。

## M4 负面定性高证据门槛 + 检索边界披露

**规则**：
1. 指控类负面定性（山寨/造假/跑路/恶意）的证据门槛**高于**正面结论：至少两类独立渠道（搜索引擎 + GitHub/官网/社区任一）交叉命中才允许写入结论区；
2. 「搜不到」类否定性证据必须附检索边界——渠道、关键词、日期——并显式声明「检索时滞：新事物可能未被收录」；
3. 负面定性必须附「证伪动作清单」：做什么能低成本推翻该定性，供用户复核。
4. 当前环境无检索能力时，指控类定性**一律进 ❓ 区**（与红线 3 呼应）——「查不了」不能降级为「凭印象判」。
5. **模型脑内断言视同 C 级信源**（v0.6）：模型自身生成的具体断言——版本号、issue 号、数字、「已知问题」——无出处时一律进 ❓ 并附溯源动作，不得直接进结论区或标 🐯。理由：幻觉天然具体，越具体的断言越容易通过「具体性」过滤（L2 第一问），而「搜不到≠不存在」的时滞声明在此反向生效——幻觉查不到反而显得更像真的。

- **来源**：案例 D1（把「搜索引擎搜不到」当「不存在」，将 10 万 Star 开源项目误判山寨，用户质疑后换关键词即现形）；红队评审-v1 B1（具体≠真：幻觉与真坑评级正相关）。

## M5 样本量强制声明

**规则**：容量/速率/成本类结论必须显式声明输入数据的**样本量、覆盖期、遗漏场景**（如「样本=2 天账本，未覆盖赶工周」）。样本不足以支撑结论时，降级为「待验证假设」并列出补数据动作。**数据画像缺失本身就是一个必须上报的坑。**

- **来源**：案例 D3（两天均值 $29/月 vs 用户真实日耗 5–10 亿 token，偏差 3–7 倍；两天恰好是低强度日，均值掩盖分布）。

## M6 异常信号触发器 + 条款层级枚举

**规则**：
1. **too-good-to-be-true 自动升档**：异常便宜/顺利/优惠 → 升 T2 深审，触发三问——谁在补贴？为什么？代价藏在哪？
2. **条款层级枚举**：涉及套餐/合同/额度时逐层填值：总额度 / 单项额度 / 促销加成 / 窗口限制 / 过期规则 / 隐藏费用。**缺层即坑**（读不到就标「该层不透明」）。
3. **优势归属检验**：每项候选优势回答「在用户的实际使用路径上是否成立」（如「CLI 专属缓存红利」对走 API 接入的用户不存在）。

- **来源**：案例 D6（$10 卖 $120 未触发深挖；用户反问后才发现 $70 总闸 vs $100 单模型促销的纸面数字、以及 harness 红利只属于自家 CLI）。

## M7 三态披露契约

**规则**：报告中每条陈述落入且仅落于一态：

| 态 | 准入 | 必附 |
|---|---|---|
| ✅ 已查证到 X | 有外部信号支撑（实测/检索/工具输出） | 证据链：来源+方式+时间+**可复核的原文/输出引用**（可粘贴复核的片段，非模型转述） |
| ❓ 未验证 | 有理由怀疑但未验证 | 原因 + 5 分钟内可执行的补验动作 |
| 🚫 盲区 | 本任务类型中系统性看不见的坑类别 | 预注册声明（类比利益冲突披露） |

三区必须显式出现，空区写「本区为空」并给**本次**判断为空的具体依据（具体事实/检查动作，模板话术不合格）。「验证通过」禁止裸用。**复查条件（v0.6.2）**：✅ 只对验证时刻诚实，不自动延续到使用时刻——高时效条目（版本/价格/库存/安全公告类）必须附复查条件（如「距验证 >24h 或目标版本变更时重跑验证器」）。

**✅ 语义说明（v0.6）**：「已验证」容易把模型的一次推理包装成事实状态——证据链三件套（来源+方式+时间）齐全只证明「查过」，不证明「查对了」（链接活着但内容过时、文档滞后于回归版本都是常态）。所以语义收紧为「已查证到 X」并强制附可复核引用：读者拿引用能自己重放这次查证，错了能当场推翻。同构于纸老虎摘免死金牌——通过不等于免检。

- **来源**：案例 D7（六次失误全靠用户质疑才修正——验证边界不透明，用户只能靠事后质疑质检）。**外部佐证（第三源，2026-10-14）**：实践者独立总结「同一会话从需求分析到自我审查全程沿用初始理解，前期判断错则后续全错」，其解法（拆独立会话审查）与公理 2「内省不算验证」同构——继 ZCode/WorkBuddy 双库收敛后，又一次独立收敛到同一机制（AI 纪要转述，consensus 级）。红队评审-v1 C1（格式合规≠结论正确）。

## M8 真实性过滤与分级

**规则**：L1 原始产出全部过 L2 过滤：每条「坑」回答「这是具体证据指向的真风险，还是放之四海皆准的叙事？」判定标准：该条是否让用户停下来查证一个具体事实/重算一个具体数字。**具体≠真**：无出处的脑内具体断言按 M4 第 5 条进 ❓。过滤后四分（v0.6 硬化）：

- 🐯 真坑（阻断级）：动手前必须处理；
- 🟡 中风险：对策必须绑可执行检查（同 M13 标准）——**裸对策降 ❓**。「有对策即可推进」若不强制对策可验证，就是全报告唯一能合法携带「未验证的安慰」的区域，虚假安全感的最优藏身处；
- 🐘 大象：今天没事、条件触发即致命——进监控区，附可观测触发信号，**且必须写明监控者三问：谁、在何时、看什么信号**。答不出监控者 → 并入 🐯 并把检查放进执行流程——报告交付后技能退场，没有监控者的监控区是精致的风险陈列柜：心理上完成处置，行动上零处置；
- 🐺 纸老虎：看似吓人大概率没事——显式列出、**不设防**（防清单通胀与资源错配）。但 v0.6 起两道门槛：**判狼需至少一条可查证据**（一次检索/一次版本核对，纯内省不算——公理 2 没有豁免位）；**摘除免死金牌**——「防后续重复挖出」特权取消，后续扫描可重新质疑（单点误判不再被流程放大成全链路免疫，且误判方向与确认偏误同向）。

- **来源**：综述 2.2（pre-mortem 的批评：产出混杂真实风险、假想原因与无人敢点的显性问题）；Doshi Tiger 框架；红队评审-v1 B2/B3（监控区无人值守；免疫通道与裸对策）。

## M9 多层检查防重叠

**规则**：T2 深审档至少分三层，各层查不同维度（层间洞不重叠）：任务语义层（需求歧义/目标漂移）、数据与口径层（样本/量纲/信源）、执行环境层（工具链/权限/缺省行为）。每层预设自己的失效模式：「如果这层漏了，下一层怎么兜？」

- **来源**：综述 4.3 Reason 瑞士奶酪模型（事故=各层防御的洞连成一线；latent conditions 可事前纠正）。

## M10 缺省行为必测

**规则**：第三方组件/参数/服务的**缺省语义默认为「未知」**。信任等级固定 `读源码 > 实测 > 官方文档 > 猜测`，报告标注每条依据的等级。两样都做不了 → 标 ❓ 并附最小实验设计。**禁止按常识推断缺省行为。**

- **来源**：案例 E1（「不传参数」在该网关=思考默认开启，default 档最贵；按常识「省略=关闭」错误）、E3（插件 never 档恰好不带 sandbox 字段，CLI 测试经验推 app-server 路径错误——源码 lib/index.js:19-30 才是真相）。

## M11 配置即验证

**规则**：产出任何配置文件/manifest 后，**必须真实加载解析一次**才允许标 ✅。写完不跑 = 未验证。已知暗雷：YAML 1.1 的 `off/no/on/yes` 布尔强转、JSON 数字精度、环境变量全字符串、shell 的 word-splitting。

- **来源**：案例 E2（思考档位配 `off` 键被 YAML 解析成 false，配置静默失效）。

## M12 坑卡回写与相似召回

**规则**：
1. 每次踩坑结束产出回写条目（格式见下）；
2. **未遂优先**：被预检拦下的坑、低损害小坑优先记录（海因里希 1:29:300:1000——未遂是大坑的先导）；
3. 下次任务进入 L1 时按任务相似度召回历史坑卡；
4. **漏报/谎报分轨**：漏报（当时 ❓ 区如实披露）可原谅、正常回写；谎报（声称 ✅ 无证据链）不可原谅、追流程根因。复盘对事不对人。

**坑卡格式**（YAML frontmatter + 正文四元组）：

```yaml
id: RD-001
domain: research-decision
title: 把「搜不到」当「不存在」
hazard_type: 事实性陷阱      # 常见错误/隐含前提/易错环节/工具链环境/事实性陷阱/逻辑漏洞
severity: 7                # S 伤害 0-10
detectability: 9           # D 隐蔽度 0-10（高D=毫无征兆）
trigger: 对新事物下负面定性时
latent_condition: 检索时滞   # 长期隐患（无责复盘二分之潜伏隐患）
verified: case-replay      # case-replay / literature / unverified
source: cases/D1
```

坑卡格式与回写流程见 `card-format.md`（单一真源 `cards/*.yaml`，四件套：描述+证据+规避动作+验证器，triggers 强制双语）。

- **来源**：综述 5.1–5.6（无责复盘、GRAI、美团 COE 相似召回、海因里希、掘金黄金三元结构）；案例 D8/E3。

## M13 验证器铸造

**规则**：预踩坑的产出物是**验证器**，不是担忧。每条 🐯 真坑必须绑定一个可执行验证器——一条命令、一次检查或一个可观测信号，其输出能让「坑在不在」变成外部事实而不是模型判断。绑不上可执行验证器的条目一律降级进 ❓ 区，不得留在 🐯 区。验证器由踩坑方铸造、由执行方运行（引擎只铸造，不代跑）。v0.6 起验证器铸造四规：

1. **判定表前置**：先写「输出 X ⇒ 坑成立；输出 Y ⇒ 坑不成立；其他 ⇒ 未判定」再执行。没有判定表，同一输出支持两个相反结论（`grep old_name` 命中 3 处＝坑存在？还是有兼容层？），执行后的解读权退回模型内省——公理 2 从后门回来，且解读会朝铸造时的预期（它已判 🐯）偏移；
2. **副作用三分类**：验证器标注 只读/写/不可逆。不可逆类默认禁用（防坑技能不得在执行层引入新坑向量，如挨着生产实例跑 `pg_restore`）；写类需用户点头，并附**副作用预算与回滚方式**——配额/限流计数等累积型副作用按账户状态级评估，不止单操作级（v0.6.2）；
3. **环境存在性预检**：附一条存在性检查（`command -v` / 路径探测）。预检失败 → 降 ❓，禁止误读「命令失败/路径不存在 = 没装 = 无坑」；
4. **执行结果回填**：报告中验证器后必须跟「执行结果」栏（含「未执行+原因」），结果对照判定表决定该坑分级去留——只铸造不回填，「必须实测」就退化成「报告里出现过一条命令」的形式履行。

**覆盖类型声明**：盲区声明须注明本报告验证器覆盖 静态/动态。并发、负载、特定输入序列类坑只在执行动态过程中成立，任务前静态检查对它们结构性失明——动态覆盖为 0 的任务类（迁移/压测/并发改造）必须显式声明「事前验证对本任务类部分失效」。

- **为什么有效**：一份列满「可能出问题」但没有任何可执行检查的报告，与愿望清单工程等价——都不能改变失败概率。验证器把「风险」转化为「一次廉价的证实/证伪」。判定表前置对应 LLM-as-judge 文献的评分标准预注册（pre-registration）：先声明标准再观测，显著压低位置偏差与确认偏差（arXiv:2411.15594 综述；2406.07791）。
- **反面示例**：「注意依赖版本兼容」——无验证器，纯担忧。
- **合格示例**：「`node -e "require('js-yaml')"` → 判定表：退出码 0 ⇒ 依赖可用（CODE-012 不成立）；报错 ⇒ 命中 → 执行结果：已执行，退出码 0，坑关闭」——可执行、可观测、可归因、闭环。
- **来源**：WorkBuddy 方法论 v0.3 定位公理 4 + 3.8 验证器本身也要被验证（弱验证器给出虚高信心，比没有更糟——参照 CODE-004 测试假绿）；红队评审-v1 D1–D4（歧义/副作用/不回填/静态盲区）。
- **融合记录**：2026-10-15 双库融合时由 WorkBuddy 侧机制并入 ZCode 机制序列（原 ZCode 硬约束 6 的「附带检查动作」升格为「绑定验证器 + 降级规则」）。

## T2 红队对抗操作化：破 → 立 → 裁 → 监测（v0.6.1 并入）

> 来源：AMiner 报告第 2 章（决策科学五大制度化异议方法的 AI 压缩形态；Schwenk 1990 元分析：魔鬼代言人优于专家直采，辩证探询优势不稳定——「让 AI 挑刺有效，让 AI 自辩自评未必」）。并入 T2 的「红队对抗」，不新增流程步骤。

1. **破（禁止支持）**：红队阶段明确禁止输出支持性评价——不设此约束，模型默认收敛到「先优点后缺点再和稀泥」的平衡话术，不产生新认知。反驳覆盖六维度：遗漏信息、盲目乐观假设、不可逆成本、机会成本、最坏风险、情绪偏差。产出是问题清单而非结论。
2. **立（逐条回应）**：辩护方必须逐条回应「破」的每条质疑，不许换方向重新堆砌——若两不相干，说明支撑逻辑断裂。
3. **裁（禁五五开）**：显式禁令「不刻意平衡观点、拒绝强行五五开」。裁决四要素：优势方判断（哪边更充分）／最大未知风险（只指一个致命变量）／结论反转条件（可观测触发事件）／**不决策的代价**（时间窗/金钱/机会三维量化——最常被漏的要素）。
4. **监测（可证伪通道）**：反转条件落成「一个可监测指标 + 一个写进日程的复查时间点」；复查日触发则回到「破」重跑。对应 M8 大象档的监控者三问——大象写不出监测者时并入 🐯，正是本步的降级路径。

**失效边界三判据**（何时这套流程失效）：①输入完整度——把决策背景讲给一个不知情同事听，对方复述不出三个核心假设与最大顾虑 = 背景太薄，先补背景再对抗；②时效性——关键事实发生在模型训练截止之后，反驳可信度系统性下降；③过度使用——同一决策连续 3 轮对抗后新增实质问题趋近于零，剩余犹豫来自情绪而非信息，需要拍板而非再分析。
