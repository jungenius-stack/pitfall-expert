# DoD：踩坑完成标准（六条过程标准）

> 全部是过程指标，无一条要求「结果上没有坑」——保证结果完美只会催生谎报；保证过程完备与披露诚实，才是可持续的质量底线。

一次踩坑「完成」，当且仅当六条全满足：

| # | 标准 | 机检项（dod_check.py） |
|---|---|---|
| 1 | **档位已声明**：报告头部含档位 T0/T1/T2 及升降档触发记录 | ✅ 检查「档位」字段存在且合法 |
| 2 | **画像已生成**：第 0 节存在；画像缺失时其影响已声明 | ✅ 检查 `## 0` 节存在 |
| 3 | **覆盖率 100%**：所属领域坑卡逐卡扫描，附「N/N」计数 | ✅ 检查「坑卡扫描」行存在且为 N/N 形式 |
| 4 | **🐯 三态完整**：每条真坑带 ✅证据链 或 ❓补验动作 | ✅ 检查 🐯 节每条含「三态」行 |
| 5 | **披露率 100%**：❓ 未验证区与 🚫 盲区声明两节存在（空也写「本区为空」） | ✅ 检查 `## 3`、`## 4` 节存在且非占位空白 |
| 6 | **回写就绪**：第 6 节存在 | ✅ 检查 `## 6` 节存在 |

**判定规则**：
- 六条全过 = **合格**（哪怕事后发现漏了大坑——走漏报轨，正常回写坑库）；
- 任何一条虚报 = **不合格**（哪怕碰巧没出事——走谎报轨，5 Whys 追流程根因）。

**机检与人的分工**：机检只能证明「结构完整」，不能证明「内容真实」——证据链的真伪、补验动作的可执行性仍需抽查。这正是瑞士奶酪模型的应用：机检是一层，用户抽查是另一层，两层查不同的洞。

机检用法：

```bash
# 检查一份踩坑报告
python3 scripts/dod_check.py <报告.md>

# 坑卡校验（cards/*.yaml，贡献前必跑——引擎严格校验 12 必填字段）
node -e "const {loadCards}=require('../../engine/src/scanner'); const r=loadCards('../../cards'); console.log(r.cards.length+' cards', r.errors.length? JSON.stringify(r.errors):'✓')"
```

> 坑卡校验由引擎 `loadCards` 承担（字段完整性 + 枚举值 + S/O/D 类型），dod_check.py 专注报告机检——职责分离，各自测各自的。
