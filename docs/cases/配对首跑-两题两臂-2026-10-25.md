# 配对首跑：两题 × 两臂（2026-10-25）

> 依据《评测协议 v0.2》§三的最小可行首跑：同一题目、同一模型、同一夹具（哈希核验），裸跑臂 vs 技能臂各跑一次，唯一差异=开工前是否按 SKILL.md 流程执行。**n=1/臂/题，属演示跑，任何数字不得用于对外声称效应**（协议 §六）。

## 一、题目与地面真值（出题人=本轮会话，夹具均在 /tmp）

### T1 · YAML `on:` 布尔坑（对应真实世界 PyYAML #679 / 卡 CI-004 场景）

- 夹具：`.github/workflows/ci.yml`（映射形 `on:`）+ `deploy.yml`（列表形 `on: [push, workflow_dispatch]`）。
- 任务：用 PyYAML 写脚本列出每个 workflow 的触发事件。
- 真值（出题人亲测）：`yaml.safe_load` 下两文件顶层键均为 `True`（`on` 被解析为布尔）；正确输出 = ci.yml: push, pull_request；deploy.yml: push, workflow_dispatch。

### T2 · CSV 多重坑（卡 CODE-013/014 场景）

- 夹具：`users.csv`（sha256 `546ae7ff…d242b`），内含 4 个埋设坑：UTF-8 BOM、引号千分位 `"1,200"`、空省份行 `,20`、**精确重复行 `浙江,80` ×2（核心暗坑）**。
- 真值（出题人设计意图）：BOM/千分位必须正确解析；空省份行的两种处理均可接受但须**显式披露**；精确重复行按数据录入错误应去重（浙江=80）——至少必须**被发现并作为口径问题上报**，静默双计（浙江=160）判踩坑。

## 三、裁决（结论先行）

**本轮没有出现任何一格「裸跑踩坑、技能避坑」的对比**：T1 两臂都躲开了坑（该坑太著名，已被当前模型内化）；T2 两臂踩了同一个埋设暗坑（精确重复行），技能臂的守恒校验（各省和=总数列总和）从原理上检不出重复行——重复不破坏守恒。

### 本轮真正值钱的三个发现

1. **守恒校验的盲区（新卡候选，两臂同盲）**：求和类任务里，行级精确重复无法被「分项和=总和」类守恒校验检出；技能臂 V1–V5 五个验证器全 PASS 却交付了双计结果——验证器体系对「数据层歧义」存在结构性盲区，需显式重复行检查器（与 CODE-036「代码正确≠数据正确」同族，但角度不同：那是代码-数据错位，这是校验器-歧义错位）。
2. **题目难度校准规则实证**：著名坑（YAML 布尔、BOM）对当前代模型已无对比度——协议「入题门槛：裸跑预筛确实踩坑」从此不是建议而是硬门槛，否则跑再多次也是平局。
3. **裸跑臂虚构自述**：T2 裸跑臂交付时声称「目录原有同名 summarize.py（内容同样正确）已覆盖」，但目录时间戳与哈希证明该文件从未存在（其自建初版被自己误归因为他人成品）——模型自述即便是无关紧要的细节也可能失真，佐证「自述不作数、只认产物复跑」的裁决纪律。

### 成本

技能臂 token 开销为裸跑臂的 1.4（T2）～ 2.9（T1）倍。本轮多买的增量是流程披露与边界自测深度，**不是坑拦截差分**。

## 四、诚实边界

- n=1/臂/题，单模型（会话同源 GLM 系子代理），夹具 2 文件/8 行，无统计效力；
- 出题人=卡库作者关联方，T1/T2 均为按既有卡场景构造，按协议属「背题高危」侧，仅作流程演练；
- 两臂子代理环境一致（同机、PyYAML 预装、夹具哈希一致），但 T1 曾发生**两臂共用目录导致技能臂覆盖裸跑臂脚本**的执行事故（T2 已改为物理隔离目录 `-a`/`-c`），T1 裸跑臂脚本本体未保留，其输出以自述+主会话夹具真值比对为准。

## 五、回写候选（待确认后入 cards/ 或登记簿，本轮不落库）

1. **新卡候选（code 域）**：求和/汇总任务的「守恒校验不防精确重复行」——症状：各分项和=总数全对，结果仍双计；检测：显式 `df.duplicated()` / 行级精确重复计数并上报口径；证据：本轮两臂同盲实录。
2. **元坑登记候选**：评测配对执行时两臂必须物理隔离工作目录（T1 覆盖事故）。

## 七、T3 已就绪待跑（2026-10-25 晚，子代理并发额度占满中断）

- **选卡依据**：SCI-002「join 静默行爆炸/行丢失」——fix 含 `validate=`、join 前后行数断言、右表显式去重；verifier 现成。证据源即真实社区案例（SO q/37095161 高票 + Python Alchemist 笛卡尔爆炸分析）。
- **地面真值（pandas 6.x 亲测）**：naive `merge` 行数 5→7 无报错，李四 900、总 1680（静默双计）；正确（右表去重）= 张三 280、李四 450、王五 500、总 1230。

## 八、T3 预筛结果：题目作废（2026-10-25 深夜续跑）

### 诚实边界（比结论更重要）

1. **卡是看着这个夹具的失败写出来的**——这证明的是「回写闭环能工作」（评测暴露缺口 → 补卡 → 同题拦下），**不是**卡的泛化能力。卡的 triggers 是通用词（汇总/求和/统计/sum/groupby），未含“省份”等题目专属词，但 description 引用了本案。**泛化检验是下一步必做**：换一个完全不同领域、藏重复行的汇总夹具（如按地区汇总销售额），不改卡直接跑。
2. n=1～2/臂，单模型，8 行夹具；判定“避坑”用的是披露级标准（发现并上报口径），stdout 数字仍是 160——这符合 §一 预设的真值规则，但若用户要的是“直接给去重后的数”，则是部分得分。
3. 哨兵卡在 /tmp，**未入生产卡库**；是否晋升为正式 CODE-046 由用户决定。晋升前须跑 `node eval/gate.js` 确认跨域误命中增量为 0（triggers 含 统计/sum/total 等宽词，电池题 3「报价表总金额」大概率新增命中——那是真阳性，但需人工确认而非默认放行）。

### 可复用的出题方法（两轮实证后的 SOP）

1. **选坑先选卡**：从 `cards/` 里挑有具体 fix/verifier 的卡，坑型必须是“代码对、结果错、无报错”的静默型（D 值高）；
2. **裸跑预筛 ×2**：至少 1 次真踩才入题——出名坑（YAML 布尔、BOM、merge 重复键）当前模型全躲，直接作废；
3. **物理隔离**：每跑独立目录，夹具 sha256 入档，失败/中断的子代理可能留下半成品；
4. **只认复跑不认自述**：子代理两轮三次“目录里原有别人的文件”自述均不可靠；
5. **缺口即卡**：两臂同踩 = 卡库真空，走回写→哨兵→同题重跑→**异题泛化**四步，缺最后一步不得声称“卡有效”。
