## Q1 警告疲劳：效应量与决定属性

### 查到了什么

**浏览器安全警告（效应量）**
- 规模最大的现场证据：2520 万次警告曝光的遥测数据显示，用户无视 Chrome SSL 警告的比例高达 **70.2%**，而无视 Firefox 恶意软件/钓鱼警告仅约 10%、Chrome 约 25%、Firefox SSL 约 33%——同一用户群对不同警告的依从差异可达 7 倍（[Alice in Warningland](https://www.aminer.cn/pub/5390bda020f70186a0f47d37)，USENIX Security 2013，无 DOI）
- 习惯化梯度：Chrome SSL 警告（missing www 类）点击率随暴露次数单调上升，约 21%→30%→37%（第一至第三次暴露），且用户对最常见错误类型点击得**更快**——与"警告疲劳/注意力是有限资源"理论一致（[Alice in Warningland](https://www.aminer.cn/pub/5390bda020f70186a0f47d37)，USENIX Security 2013）
- 主动式（强制停顿）警告 vs 被动式（状态栏提示）：钓鱼攻击实验中 97% 参与者至少上当一次，但看到主动警告后 79% 听从；被动警告仅 1/60 人理会——**呈现强度**是头号决定因素（[You've Been Warned](https://www.aminer.cn/pub/5390a01420f70186a0e48308)，CHI 2008，DOI: 10.1145/1357054.1357219）
- 按警告科学原则重新设计的警告显著优于现役警告，但"所有条件下仍有过多参与者做出危险行为"——作者结论是应**最小化警告的出现频率**而非仅优化警告本身（[Crying Wolf](https://www.aminer.cn/pub/5390ac5720f70186a0eb6e0a)，USENIX Security 2009，无 DOI）

**神经层面机制**
- fMRI 直接观测到对重复警告的重复抑制（repetition suppression），即习惯化发生在神经响应层面而非仅行为层面（[Why Users Habituate to Security Warnings: Insights from fMRI](https://www.aminer.cn/pub/5f0e9f089fced0a24b11a406)，2014）
- 干预设计反例：**多态警告**（每次改变外观）在 fMRI 实验（n=25）和真实桌面实验（n=80，鼠标追踪测量）中均显著更抗习惯化——"可变性"是可验证的抗习惯化属性（[From Warning to Wallpaper](https://www.aminer.cn/pub/58d82fbdd649053542fd335c)，JMIS 2016；AMiner 链接）
- 行为侧证据：用户对同一安全警告的依从在约三次暴露后即显著下降（[Users Aren't (necessarily) Lazy](https://www.aminer.cn/pub/555045ff45ce0a409eb5b267)，ICIS 2014；及 [Habituation Effects in Computer Security Warning](https://www.aminer.cn/pub/5aed14d117c44a4438158061)，Information Security Journal 2018）

**医疗告警疲劳（效应量）**
- ICU 真实负荷：ICU 每床每天平均 **187 次可听警报**，抽检的 12,671 条心律失常警报中 **88.8% 为假阳性**；93% 的真性室速警报持续时间不足以需要处置——绝对数量与低信息价值共同驱动疲劳（[Drew et al., PLoS ONE 2014](https://www.aminer.cn/pub/55a69aa765ce054aad6d8afb)）
- 去敏化的直接检验：回顾性队列显示，对同一药物相互作用警报的**每次既往暴露都会提高覆盖率**（去敏化机制成立），而工作量/工作复杂度的解释力远弱于此（[Ancker et al., BMC Med Inform 2017](https://www.aminer.cn/pub/599c780b601a182cd2598c4d)，DOI: 10.1186/s12911-017-0430-8）
- 缓解方向的反面证据（可用的"属性"）：基于溯源分诊自动排序警报的系统估计可减少 84% 假警报量——**可操作性（分诊/优先级）**而非数量本身决定警报是否被处理（[NoDoze, NDSS 2019](https://www.aminer.cn/pub/5ccc1dd1e1cd8ed58cdc87a5)）

**软件工程侧（构建/静态分析警告被忽视）**
- 眼动实验（n=56）：开发者实际会读编译错误信息（占任务时间 13–25%），阅读难度显著预测任务表现——警告**可读性**是被忽视的关键变量（[Do Developers Read Compiler Error Messages?](https://www.aminer.cn/pub/599c7bee601a182cd2774416)，ICSE 2017）
- 眼动实验中仅约 **14%** 的开发者在存在安全缺陷的场景下实际阅读了静态分析警告文本；且给出警告组的缺陷修复率并不高于（甚至略低于）无警告组——"提示存在"≠"提示被消费"（[Smith et al., TSE 2016](https://www.aminer.cn/pub/57d063feac443673542980df)，DOI: 10.1109/TSE.2015.2576442）
- 访谈（n=20）：假阳性与**呈现方式**是静态分析工具不被使用的首要障碍，开发者明确要求交互式修复辅助（[Why Don't Software Developers Use Static Analysis Tools?](https://www.aminer.cn/pub/5390bb1d20f70186a0f3ceca)，ICSE 2013）
- 真实使用挖掘：SonarQube 绝大多数违规从未被修复，且响应集中在违规刚引入的短窗口内，遗留违规基本被放任（[Are Static Analysis Violations Really Fixed?](https://www.aminer.cn/pub/55a4ad8bc91bf3b1cc435247) 正式版，DOI: 10.1109/ICPC.2019.00040）

### 搜了但没搜到
- 软件工程语境下"暴露次数→忽略率"的纵向剂量-反应研究（类比 Alice in Warningland 的习惯化梯度）没有直接对应物；静态分析文献多为相关性挖掘，缺因果实验
- 编译警告/构建警告领域被用户点名的"To Fix or to Fold"（GitHub 构建警告处理）在库内未命中
- 中文的原始实证研究（告警疲劳实证基本为英文文献）

### 搜不到及原因
- "AI 助手审批弹窗的习惯化率"这类针对 LLM 工具的警告疲劳数据不存在（与 Q4 结论一致）；目前只有灰色文献把 Alice in Warningland 的数字外推到 agent 审批场景（[tianpan.co 分析](https://tianpan.co/blog/2026/07/07/the-approval-prompt-nobody-read)、[digitalapplied.com 分析](https://www.digitalapplied.com/blog/default-deny-vs-default-allow-agent-permissions)），非同行评审

## Q2 检查单类干预的对照实验

### 查到了什么

**阳性结果（按证据强度排序）**
- 唯一真正的随机设计阳性：挪威两院 **stepped-wedge 整群 RCT** 显示 WHO 手术安全清单降低并发症与住院时长（[Haugen et al., Ann Surg 2015](https://www.aminer.cn/pub/56d8a645dabfae2eee8e0e7c)，DOI: 10.1097/SLA.0000000000000716）
- 其二次分析给出效应量与机制：高质量实施（三部分全做）下手术部位感染率 7.4%→3.6%（OR=0.52, 95% CI 0.38–0.72），且**实施保真度中介了结局**——抗生素时机、保温等过程指标改善是因果通路（[Haugen et al., Ann Surg 2019](https://www.aminer.cn/pub/5c136e51da56795a08ac5238)）
- 患者级 RCT（单中心、发展中国家，350/350）：清单组伤口、腹部、出血并发症及死亡率均显著下降（均 p≤0.04）；亚组显示**清单填写不完整的患者结局更差**（[Chaudhary et al., J Gastrointest Surg 2015](https://www.aminer.cn/pub/55a6b8d565ce054aad72ac99)）
- 最大规模观察性阳性：全球 8 院 7646 例前后对照，死亡率 1.5%→0.8%（P=0.003），并发症 11.0%→7.0%（P<0.001）——但无同期对照，后世认为高估（[Haynes et al., NEJM 2009](https://www.aminer.cn/pub/65b8f2ff939a5f40822a8d2c)，DOI: 10.1056/NEJMsa0810119）
- 全路径综合清单（SURPASS，含病房/出院环节）+ 5 家对照医院：每百人并发症 27.3→16.7，死亡率 1.5%→0.8%，对照医院无变化（[de Vries et al., NEJM 2010](https://www.aminer.cn/pub/55a3df9a65ce05cd7b3baf3ac)，DOI: 10.1056/NEJMsa0911535）
- 清单式干预的同类天花板案例：密歇根 103 个 ICU 的中心导管检查单+文化干预，感染率中位数 2.7→0/千导管日，16–18 个月时 IRR=0.34（下降 66%）且持续——但为协作队列准实验，非随机（[Pronovost et al., NEJM 2006](https://www.aminer.cn/pub/53e99937b7602d970217457e)，DOI: 10.1056/NEJMoa061115）

**阴性结果（用于校准效应上限）**
- 用户已知的 Ontario 大规模自然实验：强制推行+公开报告依从率的 101 家医院，手术死亡率（校正 OR≈0.91, P=0.13）、并发症、再入院、急诊就诊**均无显著改善**（[Urbach et al., NEJM 2014](https://www.aminer.cn/pub/678be13aae8580e7fffa7375)，DOI: 10.1056/NEJMsa1308261；[ICES 官方摘要](https://www.ices.on.ca/news-releases/study-shows-introduction-of-surgical-safety-checklists-in-ontario-have-not-reduced-post-operative-mortality-or-complications)）

**条件归纳（何时有效/何时归零）**
- 效应集中于**基线过程依从度低**的场所（全球试点基线并发症 11%→7%、荷兰 27.3→16.7；而 Ontario 高基线体系归零）——基线依从度决定剩余可捕获空间
- **实施保真度是中介变量**：挪威与印度数据均显示"纸面完成"（checkbox compliance）不改变结局，只有改变实际护理过程的部分才产生效应（[Ann Surg 2019](https://www.aminer.cn/pub/5c136e51da56795a08ac5238)、[J Gastrointest Surg 2015](https://www.aminer.cn/pub/55a6b8d565ce054aad72ac99)）
- 设计最强（随机）的研究效应量小于设计最弱（前后对照）的研究——**效应上限随方法学严格度单调收缩**，Ontario 结果提示在成熟体系中的真实效应可能≈0

### 搜了但没搜到
- Urbach 团队后续的 Ontario 癌症手术/更长时窗随访研究未在本次检索范围内补全
- 医疗之外的检查单 RCT（航空、核工业等高风险行业）未命中可用的对照实验——这些领域几乎不发表 RCT

### 搜不到及原因
- "checklist + randomized + AI/coding"的交叉检索无命中——检查单 RCT 的证据库止于医疗领域；AI 任务场景的检查单 RCT 目前不存在（属研究空白，与 Q4 互证）

## Q3 LLM-as-judge 的失效模式与防污染设计

### 查到了什么

**失效模式实证**
- 奠基性实证：GPT-4 作 judge 存在位置偏差、冗长偏差与自增强偏差，MT-Bench 上的高一致性部分是伪象（[Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena](https://www.aminer.cn/pub/648697e6d68f896efaa87857)，NeurIPS 2023，arXiv:2306.05685）
- 位置偏差可被系统性利用：仅调换回答顺序即可让 Vicuna-13B 在 80 题中 66 题上"击败"ChatGPT（arXiv:2305.17926，[AMiner](https://www.aminer.cn/pub/647572e0d68f896efa7b7827)，ACL 2024）
- 自偏好有因果基础：GPT-4/Llama-2 开箱即有非平凡的自识别能力，微调实验显示**自识别能力与自偏好强度线性相关**且通过混淆对照（arXiv:2404.13076，[AMiner](https://www.aminer.cn/pub/662715c213fb2c6cf65d812b)，NeurIPS 2024）
- 无参考答案时不可信（用户已知的 BFF-Bench 之外无新增）：judge 只有在自己能答对时才与人类专家高度一致；提供专家金标参考可大幅缓解（BFF-Bench，arXiv:2503.05061，[AMiner](https://www.aminer.cn/pub/698be3049be8eb7c4bb687b0) 为 ICLR 2026 后续 BiasScope，本体详见 [arXiv 页](https://arxiv.org/abs/2503.05061v4)）
- 偏差类型学：系统性量化了 12 种 judge 偏差（CALM 框架），高级模型在特定任务上仍有显著残余偏差（[Justice or Prejudice?](https://www.aminer.cn/pub/66ff683801d2a3fbfcb8154c)，ICLR 2025）
- 位置偏差的独立系统调查（[Judging the Judges](https://www.aminer.cn/pub/66b18cbe01d2a3fbfc7bd09e)，ICLR 2025）与自偏好的量化追踪（[Self-Preference Bias in LLM-as-a-Judge](https://www.aminer.cn/pub/672195e901d2a3fbfc6ab4b4)，ICLR 2025）
- **对 AI 辅助编码任务的直接失效证据**：LLM 作代码审查者存在系统性**过度矫正**——把正确实现错判为不合规，且更详细的提示（要求解释与修正）反而导致更高误判率（[Are LLMs Reliable Code Reviewers?](https://www.aminer.cn/pub/69a645b89be8eb7c4b104238)，Automated Software Engineering 2026）

**已验证的防污染/防偏差设计**
- 专家金标：专家撰写的参考答案使 judge 与人类专家一致性大幅回升（BFF-Bench，arXiv:2503.05061）
- 客观真值+持续换题：按月用新发布材料更新题目、按客观标准答案自动评分，同时防污染和防 judge 失效（[LiveBench](https://www.aminer.cn/pub/667e191d01d2a3fbfc79d2e2)，ICLR 2025，arXiv:2408.00759）
- 时间分段评测：按题目发布时间切分训练/评测窗，可稳定检测出 GPT-4o/Claude/DeepSeek 等的污染（[LiveCodeBench](https://www.aminer.cn/pub/65f25a4213fb2c6cf6e10cdf)，ICLR 2025，arXiv:2403.07974）
- 盲评+随机顺序人类投票：Chatbot Arena 平台级盲评设计（[arXiv:2403.04132](https://www.aminer.cn/pub/65ea773a13fb2c6cf61fa015)，ICML 2024）
- 多 judge（异构陪审团）：由不同家族小模型组成的 Panel 在 3 种 judge 设置、6 个数据集上**超过单一 GPT-4 judge**、更少 intramodel bias、成本降至 1/7（[Replacing Judges with Juries](https://www.aminer.cn/pub/6630514301d2a3fbfcc145a4)，arXiv:2404.18796）
- 位置平衡+多证据校准+人机回环：三种简单校准策略显著缓解偏差、逼近人类判断（arXiv:2305.17926，[AMiner](https://www.aminer.cn/pub/647572e0d68f896efa7b7827)，ACL 2024）

**必须报告的反例（防污染设计自身也会失效）**
- 盲评人类投票同样可被操纵：针对性投票操作即可改变 Chatbot Arena 排名（[Improving Your Model Ranking on Chatbot Arena by Vote Rigging](https://www.aminer.cn/pub/679ae6afae8580e7ff8bd464)，ICML 2025）——"盲评"不是防污染的充分条件

### 搜了但没搜到
- "风格相似度→judge 偏好"的独立效应分解论文（BFF-Bench 已含此发现，未找到更细粒度的单独研究）
- 多 judge 共谋（judge 间相关性导致的系统性错误）的实证量化

### 搜不到及原因
- 针对 **coding agent 产出**（而非单轮代码生成）的 judge 失效专项研究尚未出现——现有代码侧 judge 研究止于单文件/单任务粒度（上述 overcorrection 论文是目前最接近的）

## Q4 2025–2026 年对 AI coding agent 的 guardrail/中间件/事前提示效果评测

### 直接回答：没有

**截至本次检索（2026-10-24），没有找到任何对"事前提示/警告/中间件 guardrail 干预 AI coding agent"做人类效果评测（依从率、警告疲劳、最终产出质量、RCT 或准实验）的同行评审论文。明说：这一文献尚不存在。**

### 查到了什么（相邻但不等价）
- 最接近的"干预效果"证据是负面的：用户对照实验中，使用 AI 助手的参与者写了**更多**不安全代码且更自信；论文测试的安全强化提示变体（security-tuned prompt）**未能显著降低不安全代码比例**——这是"事前提示对 AI 辅助编码无效果"的唯一直接实证（[Do Users Write More Insecure Code with AI Assistants?](https://www.aminer.cn/pub/6369c8d290e50fcafde89673)，CCS 2023，arXiv:2108.03303）
- guardrail 系统的**构建**（非人类效果评测）：AgentSpec 运行时约束 DSL 在代码执行/具身/自动驾驶任务上阻断 >90% 不安全执行——但评测对象是模拟 agent 行为，无人类依从维度（[AgentSpec](https://www.aminer.cn/pub/67e20ea5163c01c8503dfee0)，ICSE 2026）
- agent 风险**基准**（非干预评测）：LM 仿真沙箱系统性枚举 agent 危险行为（[Identifying the Risks of LM Agents with an LM-Emulated Sandbox](https://www.aminer.cn/pub/6514e2043fda6d7f062dcb33)，ICLR 2024，arXiv:2309.15817）
- 架构/分类学（无效果数据）：多层运行时护栏的瑞士奶酪模型参考架构（[Swiss Cheese Model for AI Safety](https://www.aminer.cn/pub/66b1846001d2a3fbfc5fc28b)，ICSA 2025）；LLM 软件开发 agent 的能力/失效/治理护栏映射综述（[LLM Agents in Software Development: A Systematic Mapping Study](https://www.aminer.cn/pub/6a8e242a0a96f8c83c7d4e28)，INES 2026）
- 相关的 agent 行为发现：LM agent 可能**无法依据自身的风险知识行动**——知道风险仍执行（[LM Agents May Fail to Act on Their Own Risk Knowledge](https://www.aminer.cn/pub/68a52c30163c01c850844a20)，COLM 2025）
- 工业界中间件产品（灰色文献，无公开效果评测）：拦截 coding agent 工具调用并给 allow/deny/ask 裁决的实验性方案（[Prempti/Falco](https://prempti.falco.org/)）、对 Cursor/Copilot 运行时提示与回包做 Allow/Redact/Block 的企业策略（[Fiddler](https://www.fiddler.ai/blog/ai-coding-tool-security-policies)、[Fiddler 提示注入防护](https://www.fiddler.ai/blog/prompt-injection-prevention-coding-agents)）、600 人 SaaS 公司的部署案例（[Cloudanix](https://www.cloudanix.com/use-cases/securing-ai-coding-agents-at-scale-for-enterprise-development-teams)）——全部为博客/案例，无一含对照评测

### 搜了但没搜到
- "guardrail + coding agent + effectiveness/RCT/user study"、"approval prompt + compliance/fatigue + agent"、"pre-task checklist + LLM agent + evaluation" 等组合均无学术命中
- 2025–2026 年论文中把 Q1 的警告疲劳范式（暴露次数→依从率）移植到 agent 审批场景的研究：零

### 搜不到及原因
- 领域时间窗太窄：agent 审批/中间件类产品集中出现于 2025 末–2026 初，尚未进入同行评审周期
- 效果评测需要长周期人类行为数据（依从率、习惯化曲线），工业界没有公开动机发布负面结果，学术界实验基础设施（真实的 agent 使用遥测）尚未建立
- 这正是当前的研究空白——你若做此类实验设计，Q1 的习惯化梯度（~3 次暴露即显著下降）与 Q2 的保真度中介结论是目前最可用的先验校准

---

## 一句话总结

事前警告类干预的实证证据高度一致：**依从率由具体性/可操作性/呈现强度决定，但随暴露次数单调衰减（约三次暴露即显著习惯化）**；检查单/守门类干预的效果上限由基线依从度与实施保真度决定，在成熟体系+纸面合规条件下效应归零（Ontario OR=0.91, P=0.13）；LLM judge 在无金标时不可信且存在自偏好因果链，可靠设计只剩专家金标/客观真值/异构多 judge/位置平衡四类，且各有失效反例；而把这些结论迁移到 AI coding agent 上的效果评测**尚无一篇同行评审论文**——这是明确的空白，不是"没找到"。
