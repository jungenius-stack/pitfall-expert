## 1 已查证到（✅ 附证据链）

1. **事件本体**：智谱官方技术博客《Scaling Pain：超大规模 Coding Agent 推理实践》（zhipuai.cn/zh/research/159，2026-04-29，WebFetch 全文提取成功）。原文：「我们在 GLM-5 的线上监控和用户反馈中观察到三类异常现象：乱码（garbled output）、复读（repetition），以及生僻字（rare character）。」
2. **根因是推理基础设施，不是模型本身**（A 级一手，原文可复核）：「模型本身并非根本原因」「这种『与请求内容无关、与系统压力相关』的特征」。两个 Bug：①PD 分离架构 KV Cache 竞态（Abort 信号未传播至 Prefill 侧，回收槽位被复用后遭旧请求写入覆盖）；②HiCache 加载时序缺失（Load Stream 与 Forward Stream 无同步点，Read-before-Ready）。
3. **复现难度实锤**：本地回放/同批请求重复推理数百次 0 复现；「调整 PD 分离比例并持续提高系统负载……才在约每万次请求中稳定复现 3-5 次异常」。修复后「异常输出的发生率由约万分之十几下降至万分之三以下」。
4. **独立证据（不依赖智谱自述）**：SGLang PR #22811（GitHub API 验证存在，标题原文 *"Fix for the low-probability garbled output issue in the GLM-5 series models"*，提交者 zRzRzRzRzRzRzR，已关闭）+ SGLang issue #12073（*[Bug] [HiCache]: HiCache doesn't work with PD Disaggregation*，2025-10-24，早于智谱博客半年）+ 量子位报道（qbitai.com/2026/05/412585.html，2026-05-01，技术细节交叉一致）。
5. **唐杰课堂确有其事**（B/C 级）：多路搜索一致指向唐杰在清华课堂坦白 GLM-5.3 降智真相并拆解 DeepSeek/Kimi 路线（推文 x.com/NFT_Chen/status/2115704696904258020 及后续帖）。课堂口径与官方博客一致的部分（Scaling Pain）成立。

## 5 决策建议

**口径修正（本次最重要发现）**：用户转述「模型放大过程中出现复读乱码」与官方事实不符——复读/乱码根因在**推理服务侧**（SGLang 引擎 KV Cache 管理竞态），官方明言「模型本身并非根本原因」。原文「Scaling」双关（参数规模+Infra 极限），在「课堂→听众→推文→转述」零押注传播链上被压缩成训练侧叙事。**若按原口径入库，卡会归错域、防错人。**

**塔勒布视角判断**（以塔勒布视角发言，基于公开言论推断，非本人观点）：

结论：这坑值钱，但你差点把它记歪了入库——叙事在「课堂→听众→推文→你」每一环零押注的转述中变形，这就是叙事谬误的现场标本。你手里最值钱的不是推文，是智谱自己写的那篇博客：厂商自曝踩坑实录、修复推回开源社区——这是罕见的 skin in the game，比一百条转发都硬。

火鸡问题在这案子里是教科书级的：本地回放几百次全绿，就是火鸡被喂的第一千天。「测试环境越安静，你越确信没问题，直到高负载那天」——每万次 3-5 个异常在低负载下隐身，不是不存在，是你看不见。SGLang 社区 2025 年 10 月就记录了这只火鸡，半年后厂商才定位。林迪检验：竞态在低负载下隐身这件事，分布式系统四十年历史里反复应验，不是新故事。

遍历性才算真账：万分之三看着小？单次请求的集合概率骗不了 agent 用户——一个 1000 步的 Coding Agent 任务，至少撞一次的概率 ≈ 1−0.9997¹⁰⁰⁰ ≈ **26%**（修复前万分之十几按 0.0015 算约 **78%**；算术非文献引用，异常实际集中在高负载时段与长上下文，此为均匀假设粗估）。单次低危 × 高频重复 = 高危，正是 L0 遍历性第二问的活案例。撞上之后用户在原上下文里改 prompt 死磕——赢了省几分钟，输了烧几小时，不对称在下行侧。
