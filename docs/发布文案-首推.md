## 一、从 REA（24 万星）拆出的 8 条推销结构

1. **仓库一句话 = 动词开头 + 范围承诺**。REA："Reverse engineer anything with agents, from app behavior down to native binaries."——不是"XX 是一个 YY 工具"，是"你能拿它干什么，从哪到哪"。
2. **首屏从读者的痛点瞬间开场，不是从产品开场**。REA 第一句："See a feature in an app that you want in your own product?"——先说出用户自己的欲望，产品第二句才出场。我们照此把首句改成"你的 agent 说搞定了——迁移根本没成"。
3. **三拍能力句**：做什么 → 怎么做 → 产出什么证据。一段话说完，每拍不超过一行。
4. **英雄图 = 工具真实工作的截图**，不是 logo。REA 放的是"Hopper 里 REA 正在分析二进制"的工作现场。我们暂用真实报告输出节选替代（已上 README）；**待办：补一张终端跑扫描的截图/GIF，比文字样例强一档**。
5. **能力用大表呈现**（可扫读的广度证明）：目标 | 产出什么 | 前提。我们的"能防什么"表已是此结构，保留。
6. **战绩只用可核对的具体数字，拒绝形容词**。REA："passes 3,205 original-x86 cases and reproduces all 63 compiled function bytes"。我们的对应物：10/10 回放、12/13 外部盲测、54.9%/7.8%/pass^8<25%。数字必须能追溯到回放记录，没有就用"占位，明说不承诺"。
7. **信任三件套**：本地运行/隐私 FAQ（"Does REA upload my app? — No"）、官方性声明（防仿冒，星多了再上）、**"先更新再报错"纪律**（"update REA first — changes quickly"）。前两条我们已加进 FAQ。
8. **社区循环**：showcase 征集（"used REA on something interesting? we'd love to see it"）+ 用户案例回流成内容。我们的版本：`showcase` issue → 真实案例变新卡、署名进 source_ref（已加进 README 反馈节）。

REA 没做的我们也别学的：徽章墙它没有（靠星数说话）；我们新仓库需要徽章撑门面，保留但克制（4 枚封顶）。

## 三、首发 Release Notes 草稿（v0.7.1）

**标题**：`v0.7.1 — 103 pitfall cards, six domains, and a feedback loop that turns your misses into cards`

**正文**：

```markdown
Your agent says "done" when it isn't, agrees with doomed plans, and calls single-run luck "reliable". These aren't vibes — they're measured failure modes (54.9% of WebArena failures are agents declaring solvable tasks impossible; 7.8% of "passing" SWE-bench patches are wrong; pass^8 < 25%).

pitfall-expert scans your task **before** work starts, against 103 evidence-backed pitfall cards across six domains (code / math / research & decisions / agent security / science & ML / creative writing). Every blocking pit comes with:

- the **evidence** (arXiv paper, incident log, or cross-verified consensus — never "trust me"),
- an **executable verifier** (a command whose output settles it), and
- a **three-zone honest report**: ✅ verified / ❓ unverified (5-min follow-ups) / 🚫 declared blind spots.

**Install**

    sh install.sh        # ZCode / DeepSeek Harness / Claude Code / WorkBuddy, cards included

Then just tell your agent: `先踩坑：我打算……` / `Pitfall-check this before you start: ...`
No harness? Paste the [zero-install lite prompt](docs/入门版-贴即用.md) into any chat model.

**What's honest about it**

- One domain (strategy) is a declared placeholder with zero cards — every report says so out loud.
- Misses are expected and forgivable; false "verified" claims are the unforgivable sin (our own dev meta-pitfalls are public: 17 entries).
- Local keyword matching only. No telemetry. The opt-in `--feedback` bundle excludes your task text by default.

**Found a miss or a false hit?**

    node engine/src/cli.js "the task" --feedback

paste the bundle into a [false-negative](.github/ISSUE_TEMPLATE/false-negative.md) / [false-positive](.github/ISSUE_TEMPLATE/false-positive.md) issue — real cases become new cards, credited in `source_ref`.

MIT (code) · CC BY 4.0 (cards & docs)
```
