## §1 流程落地项（本报告最大价值，不是卡）

### 1a. 评测协议 v0.2 → v0.2.1 增补（四条，全部有已验真文献支撑）

1. **「首跑即原创研究」定位**：Q4 检索确认——截至 2026-10-24，同行评审文献中**不存在**任何对「事前提示/警告/guardrail 干预 AI coding agent」做人类效果评测的论文（报告明说是研究空白，不是没找到）。落地：协议与 README 可加一句「本评测若完成，是该文献空白的首个公开数据点」——同时反向压低效应预期。
2. **效应上限声明加第二源（负面）**：Perry et al., CCS 2023（✅ arXiv:2211.03622）：AI 助手用户写了更多不安全代码且更自信，论文测试的安全强化提示**未显著降低**不安全代码比例。这是「事前提示对 AI 辅助编码无效果」的唯一直接实证（负面）。落地：评测协议§6「诚实边界」在 Ontario 阴性之外并列此条；README 效应上限段落同步。
3. **三臂首跑补两个测量**：①习惯化曲线——记录每次「卡命中→用户行动」的暴露序号（先验：约 3 次暴露后依从显著下降，Akhawe & Felt USENIX Sec'13 梯度 21%→30%→37%；Ancker BMC 2017 每次既往暴露都提高忽视率）；②A0 臂执行保真度（先验：Haugen Ann Surg 2015/2019 保真度中介结局——协议已有的「保真度≥80% 才可声称」门槛现在有 RCT 支撑）。
4. **judge 环节设计更新**：异构多 judge 陪审团（✅ Verga et al., arXiv:2404.18796：异构小模型 panel 超单一 GPT-4 judge、偏差更少、成本 1/7）优先于单 judge；时间切分防污染（LiveBench/LiveCodeBench 思路）补进防污染节；**盲评不充分反例**（Arena vote rigging, ICML 2025，🟡 未直达）备注「盲评≠防操纵」。

### 1b. 元坑登记簿候选⑳：警告疲劳对产品自身成立

T0 轻摩擦裁决（元坑①②）与「报告行数上限/分诊排序」现在有正向文献支撑：
- Crying Wolf（USENIX Sec'09，🟡 经典未直达）：结论是**最小化警告频率**而非优化警告本身；
- 主动阻断式 79% 依从 vs 被动提示 1/60（✅ Egelman CHI 2008）——未来 hooks block 模式的提示必须「少而重」；
- 多态警告抗习惯化（From Warning to Wallpaper, JMIS 2016，🟡）——若长期运行，卡呈现形式的轻量变化可延缓习惯化。

## §2 新卡候选（2 张，均 agent-security 域）

### SEC-011 审批/警告弹窗的习惯化盲批

```yaml
- id: SEC-011
  title: 审批/警告弹窗习惯化盲批（约三次暴露后依从显著衰减）
  description: "2520 万次警告曝光遥测：用户无视 Chrome SSL 警告比例 70.2%，且点击率随暴露次数单调上升（21%→30%→37%，第一至第三次），对最常见警告类型点击更快——习惯化在神经层面（fMRI 重复抑制）与行为层面都成立。呈现强度是头号决定因素：主动阻断式警告 79% 听从，被动提示仅 1/60 理会。落到 agent 场景：权限弹窗/approval 提示一路秒批、「always allow」点到底，第 N 次审批时内容根本没被读——「有提示」不等于「提示被消费」。"
  symptom: 权限/审批弹窗秒批；一路点「允许/always allow」；审批延迟越来越短；弹窗内容变了（更危险的操作）批准行为不变
  severity: {S: 7, O: 7, D: 8}
  evidence:
    source: "Akhawe & Felt, Alice in Warningland（USENIX Security 2013，25.2M 曝光遥测，usenix.org 直达验真）；Egelman et al., You've Been Warned（CHI 2008，DOI:10.1145/1357054.1357219，主动 79% vs 被动 1/60）；Ancker et al.（BMC Med Inform 2017，DOI:10.1186/s12911-017-0430-8，每次既往暴露都提高忽视率）"
    level: empirical
  fix: 高危操作用主动阻断式提示（强制停顿+具体后果描述）；常规操作分诊降级压弹窗总量（警告频率本身是变量）；审批类工具检查「批准延迟随序号单调下降」的习惯化信号
  verifier: 抽取审批日志算批准延迟对审批序号的斜率——延迟单调下降即命中；或故意夹入一个明显危险的请求，被秒批即命中
  confidence: backed_by_context
  pass_k_relevant: true
  triggers: [always allow, 允许, 一键批准, 信任此工具, 不再提示, approve, permission prompt, authorize, grant access, 全部允许]
  hazard_type: 隐含前提
  source_ref: AliceWarningland-USENX13/Egelman-CHI08/Ancker-BMC17
```

### SEC-012 模型自报风险意识不是防线（知道≠做到）

```yaml
- id: SEC-012
  title: 模型自报风险意识不是防线（知道风险仍执行；知道≠做到）
  description: "LM agent 可以具备准确的风险知识、能复述某操作的危险性，但执行时仍不据此行动（COLM 2025 实证：LM Agents May Fail to Act on Their Own Risk Knowledge）。与幻觉式完成（CODE-002）互补的镜像：模型不是不知道危险，是知道也不拦自己。含义：「模型自己会判断」「系统提示里写了注意安全」「让它先自评安全性」都不构成控制层。"
  symptom: 靠系统提示写「注意安全/危险操作先确认」当防线；让模型自评「这个操作安全吗」后按自评执行；「它这么聪明肯定知道什么不该做」
  severity: {S: 7, O: 6, D: 8}
  evidence:
    source: "Tang & Li, LM Agents May Fail to Act on Their Own Risk Knowledge（COLM 2025，arXiv:2508.13465，直达验真）"
    level: empirical
  fix: 风险控制放模型外的确定性层——权限白名单/hooks 拦截/最小权限，模型自评只作参考维度；危险操作判定用规则（命令模式/路径/资源类型），不用模型自觉
  verifier: 构造模型能正确说出风险的危险调用场景（如让它在带危险参数的 rm/deploy 上自评后再执行）——仍执行即命中（预期：会执行）
  confidence: backed_by_context
  pass_k_relevant: true
  triggers: [模型会注意, 它自己知道, 模型自评, 自检安全, safe mode, self-check, 它不会乱来, 让模型判断危险]
  hazard_type: 隐含前提
  source_ref: TangLi-COLM25
```

## §3 证据更新候选（2 项）

### 3a. CODE-039（LLM 评审代码正确性频繁误判）——补「反向误判」侧

现卡只讲「错误判正确」。补：Jin et al., Automated Software Engineering 2026（✅ arXiv:2603.00539，DOI:10.1007/s10515-026-00638-5）：LLM 代码审查存在系统性**过度矫正**——把正确实现错判为不合规，且**更详细的提示（要求解释与修正）反而导致更高误判率**。
fix 追加一句：「要求 AI 评审『解释理由+给出修正』不会更可靠，反而更高误判率（ASE 2026）——正确性闸门只能下沉到规则层。」

### 3b. RD-022（清单类干预效应可归零）——增量补强（低优先）

现卡已含 Haynes/Pronovost/de Vries/Bergs/Haugen 2019/Urbach。增量：①Haugen 2015 原始 stepped-wedge RCT（✅ DOI:10.1097/SLA.0000000000000716）；②Chaudhary 2015 患者级 RCT（清单填写不完整的患者结局更差，🟡 未直达）；③归纳句「效应上限随方法学严格度单调收缩（随机设计 < 准实验 < 前后对照）」。
说明：报告①Q2 与 RD-022 现有内容大量重叠，增量小，可只并入 ①③。
