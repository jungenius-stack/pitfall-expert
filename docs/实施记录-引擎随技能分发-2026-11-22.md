# 引擎随技能分发 + 旧副本清理（2026-11-22）

## 起因：一次真实调用跑出了旧版报告

WorkBuddy 里用户说「先踩坑：我要冲奖…」，模型：

1. 正确加载了技能（新版，含当时可用内容）；
2. 想跑引擎，副本里没有 `engine/`；
3. 于是 `find /Users/m1 -maxdepth` 全盘搜索，命中 `/Users/m1/Downloads/pitfall`；
4. 在那个目录跑了 **4 次**扫描、产出 6 份文档。

**问题**：`~/Downloads/pitfall` 是 2026-10-20 的独立旧副本，版本 `0.7.2`、**120 张卡**（真源 124），缺 CODE-048/049/050 及后续所有修正。用户看到的是过期结果，却以为是当前版本。

## 处置一：旧副本改名

- 查证：独立目录（非软链），git 干净，唯一未跟踪的 zip 与真源同名文件 **SHA-256 完全一致**（`2f5059db…`），无独有数据。
- 动作：`~/Downloads/pitfall` → `~/Downloads/pitfall-旧版-2026-10-20`。
- 目的：让后续 `find` 不再优先命中旧副本；保留数据，可逆。

## 处置二：技能副本自带精简引擎

**选择依据**（实测依赖链）：

| 组件 | 体积 | CLI 是否需要 |
|---|---|---|
| `engine/src` | 52K | 需要 |
| `js-yaml` | 1.5M | 需要（scanner 解析 YAML） |
| `@modelcontextprotocol/sdk` | 28M | **不需要**（仅 MCP server 用） |

因此只分发 `engine/src` + `js-yaml`，副本从 428K 增至 **2.0M**，避免 28M 膨胀。

### 改动点

**`sync-all-agents.sh`**

- 组装 staging 时复制 `engine/src`、`engine/package.json`、`node_modules/js-yaml`；
- **装完立即实测**：在 staging 内 `loadCards()` 必须返回 124 张且零错误，否则 `fail` 中止——不靠"复制成功"冒充可用；
- 引擎缺失/失败不阻塞技能分发（技能是模型读卡模式，引擎是加速器）；
- 输出声明「未含 MCP SDK」；
- 备份时 `rm -rf "$bdir/$NAME/engine"`：引擎可从仓库再生，避免 24 份备份 × 8 端白占数百 MB。

**`install.sh`**

- 新增 `install_engine()`，同一装配语义；
- 每个安装目标都装引擎，失败降级为"技能可用、引擎不可用"并明说。

**`SKILL.md`**

- 新增「引擎路径优先级」：①技能副本自带 → ②仓库路径 → ③声明未使用引擎；
- **显式禁止 `find /Users/m1 -name cli.js` 全盘搜索**，并记录 11-22 事故作为理由；
- 若副本无 `engine/`，视为旧版，提示重跑 sync。
