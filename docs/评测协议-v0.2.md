# 效果评测协议 v0.2（2026-10-18；v0.1 的可执行化修订）

> 要回答的唯一问题没变：**装了踩坑专家，到底拦住了多少坑、付出了多少摩擦？**
> v0.1 把方法论定完了，但卡在「≥40 个人工出题 + 人工标注」——出题人就是作者，等于背题。
> v0.2 的核心变动：**用公开基准的原始任务与人类标注替换手工出题**，并写进两条外部上限证据。

## 零、v0.2 相对 v0.1 的四项修订

| # | v0.1 | v0.2 | 依据 |
|---|---|---|---|
| 1 | 测试集手工编写 ≥40 任务 | **优先从公开基准借任务 + 借人类标注**，手工出题只补缺口 | 出题人 ≠ 标注人纪律；公开基准自带第三方标注 |
| 2 | 隐含假设「judge 可以替代人工判定」 | **明确：judge 只能减半标注，不能替代** | Limits to Scalable Evaluation（ICLR 2025）：judge 不比被评模型强时，去偏最多省一半真值标注 |
| 3 | 未设「自评判是否可信」的前置检查 | 加 **BFF-Bench 前置**：无参考答案时，judge 只在自己能答对的题上与专家一致 | No Free Labels / BFF-Bench（COLM 2026，160 题金融专家标注） |
| 4 | 只测拦截率 | 加 **效应上限基线**：接受「规模化后效应可能归零」，测执行保真度而非只测拦截率 | RD-022（Ontario 阴性 vs Haynes 阳性，中介变量=执行保真度） |

## 一、测试集来源（替代手工出题）

按「能否拿到原始任务清单 + 人类标注」排序，**逐条核实 URL 可达后才可用**（来源清单见 `eval/sources.md`）：

| 槽位 | 借用来源 | 为什么它够格 | 数据形态 |
|---|---|---|---|
| 代码/工程域 | AgentRewardBench（COLM 2025，1302 条专家标注轨迹） | 每轨迹经专家按成功/副作用/重复性三问评审 | 轨迹 + 三问标注 |
| Agent 判定 | CUAVerifierBench（COLM 2026） | 过程标签 + 结果标签双标，假阳性近零作上限参照 | 轨迹双标签 |
| 建议/决策质量 | BFF-Bench（COLM 2026，160 题 + 1200 条专家判定） | 有专家参考答案，正好检验「无金标自评」盲区 | 题目 + 专家 VERDICTS |
| 深研 rubric | ResearchRubrics（ICLR 2026，2500+ 条专家评分规则） | 2800+ 小时人工构建，最强系统遵从率 <68% | prompt + rubric + 代码 |
| 通用任务 | GAIA（466 题，HF gaia-benchmark） | 答案可精确匹配，人类 92% vs GPT-4+插件 15% | 题目 + 答案 |
| 域判定回归 | 仓库自带 10 任务噪音电池 | 已有基线，防新卡引入跨域噪音 | 10 条任务文本 |

**禁止**：直接使用卡库卡的症状/触发词改写任务（背题）。借用公开基准时**必须**保留原始措辞。

**缺口补法**：上述来源凑不满 40 任务时，才手工补，且补出的任务必须由**非本卡作者**（另一模型或用户本人）标注应命中卡 ID。

## 二、指标（在 v0.1 基础上加两项）

| 指标 | 定义 | 合格线 |
|---|---|---|
| 漏报率 | 应命中卡未被命中 / 应命中总数 | ≤15% |
| 误报率 | 命中卡与任务不相关（人工二判）/ 命中总数 | ≤10% |
| 哨兵命中率 | 哨兵卡被正确召回 / 哨兵总数 | =100% |
| 域判定准确率 | 自动判定域 = 标注域 | ≥85% |
| 摩擦成本 | T0/T1/T2 扫描耗时 + 报告行数中位数 | T0 ≤10 行、T1 ≤60 行 |
| **执行保真度**（新） | 阻断待办被真实执行的比例（抽样 10 份核对） | 记录基线，<80% 时禁用「效果提升」表述 |
| **自评一致性上限**（新） | 在「模型自己答错」的题上，其自评与专家判定的一致率 | 作为对照基线记录，不作合格线（预期显著低于总能答对的题） |

## 三、三臂对照（同 v0.1，补一条）

A 裸跑 / B 纯提示词（入门版）/ C 完整版。**新增 A0 臂**：A 组任务在**提供专家参考答案**时再跑一次——若 A0 与 A 的差值远大于 C 与 A 的差值，说明「技能的价值主要来自补足了缺失的参考答案」，而非来自预检机制本身。这一臂是防止自己给自己发奖的对照组。

## 四、执行与裁决接口（v0.1 四条 + 一条）

- 语义匹配是否上：前置判定表 = 跨域误命中不增（元坑⑰）
- 100% 扫描义务是否改抽检：哨兵命中率两轮 =100% 才可讨论
- 机检是否加语义层：反作弊样本全绿 → 人工抽查 1/10
- 档位摩擦是否超标：先砍报告行数，不动机制
- **（新）是否对外声称效果**：只有执行保真度 ≥80% 且 A0 对照完成，才可在文案里出现任何百分比

## 五、防污染与复跑

- 评测集永不入库为卡；哨兵卡只存在于 eval/ 目录（`loadCards(cardsDir)` 已支持）
- 全指标跑两轮，方向不一致即先修任务集（pass² 思想）
- CI 只跑 quick 冒烟（哨兵 3 张 + 域判定 10 任务），全量手动触发

## 六、诚实边界（新增三条）

- 本协议测「已知坑的拦截率」，测不了 unknown unknowns；拦截率 100% ≠ 安全
- **judge 参与评测的环节自带盲区**：BFF-Bench 证明无参考答案时 judge 只在自己会做的题上可信；因此任何「AI 自评我们变好了」的结论都必须附专家金标或直接作废
- **效应上限**：参照 RD-022，同类清单干预规模化后可归零（Ontario n≈21.5 万，OR=0.91, P=0.13）；本协议的指标只用于内部方向裁决，不用于对外宣称效应量
- 40 任务是最小可信规模，不是统计充分规模
