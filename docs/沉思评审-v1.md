## 十轮深思攻击

### 攻击 1：定级闸门一问是「自我审讯」，同样依赖被审的模型
- **机制**：L0 J1-b「此任务最坏会改坏什么不可恢复的东西？」
- **失效场景**：用户让 agent 改 `terraform` 状态文件。模型对 terraform 域理解浅，闸门一问答不出——但规则写的是「答不出 → 至少 T1」，**答不出的最常见原因是模型不知道该问什么，而不是任务安全**。更糟的反向情况：模型自信地答出「没有不可恢复项」（错误认知），于是合法地判 T0。同一个判断，两种方向都失效，且触发器枚举表（tier-triggers.md）里没有「terraform state」「DNS 记录」「证书吊销」这类条目时查表也救不了。
- **现有防线为何挡不住**：J1-a 显式清单是封闭枚举，攻击点是清单外的不可逆动作；闸门一问的「答不出升档」规则恰恰奖励了「编出一个看似合理的『无不可逆』答案」。
- **修复判据**：构造 ≥20 个「清单外不可逆」任务（证书/DNS/回滚窗口已过等）盲测，T0 误判率 >0 即不达标；或者把闸门一问的输出强制写入报告头，人工抽查「无不可逆项」结论的证据链。

### 攻击 2：三态契约的时间盲区——验证结果的半衰期
- **机制**：L4 ✅ 态要求「来源+方式+时间+可复核原文」。
- **失效场景**：踩坑报告在决策当天交付 ✅「v2.3.1 无该 CVE」。用户第二天才动手，期间 v2.3.2 修复公告发出、或 registry 被投毒。三态契约对**验证时刻**诚实，对**使用时刻**完全不设防——而踩坑专家的整个定位是「任务开始前」，决策与执行之间天然有延迟。
- **现有防线为何挡不住**：M7 只管报告内部的证据链完备性；DoD 六条没有一条涉及「证据有效期/建议复查窗口」。🚫 盲区区要求写「本次未覆盖范围」，但「时间未覆盖」不在此列，模板不提示就不会写。
- **修复判据**：报告模板强制 ✅ 条目带「验证时间戳 + 建议复查条件（如『动手前若距验证 >24h，重跑验证器』）」；抽查历史报告，凡是执行时间距验证 >72h 的事故，统计 ✅ 条目失效率。

### 攻击 3：L1「100% 扫描」在 200+ 卡库时变成合规表演
- **机制**：L1 第 3 路「逐卡扫描全部坑卡，100% 不许抽样」。
- **失效场景**：卡库随回写持续增长（M12 的设计目标），一年后某域 300 张卡。模型在长上下文末段的实际召回率断崖下跌——它会机械地为每张卡输出「不会踩到」，扫描计数 100%，但注意力早已耗尽。形式合规掩盖了实质漏扫，且这恰好落在 🐯 级：**规则本身制造了一个可验证的谎报形态**。
- **现有防线为何挡不住**：DoD 第 3 条只机检「计数」而非「质量」；16 条元坑里没有针对「扫描义务与上下文预算冲突」的条目。
- **修复判据**：在卡库中埋 3–5 张「哨兵卡」（trigger 与测试任务强匹配），盲跑统计哨兵卡命中率；命中率随卡数增长显著下降即为实锤。

### 攻击 4：L2 四分的判断顺序制造「洗白管道」
- **机制**：L2 两问 + 四分级；J2-a 脑内断言降 ❓。
- **失效场景**：模型对某坑有强烈先验（例如「npm install 总会装出漏洞」）。它可以先在假设倾倒阶段把这个坑表述得足够具体（挂上它记忆里的真实 issue），J2-a 只拦「模型自身生成的具体断言」，但**无法区分模型复述的真记忆与幻觉**——复述同样无出处。判定表前置（J4-a）管的是验证器，不管 L2 分级本身；于是模型可以合法地把真坑判 🐺（纸老虎），只要补一条它自己检索到的弱证据。
- **现有防线为何挡不住**：J2-d 判狼要求「至少一条可查证据」，但没规定证据的**强度门槛**——一条过时的博客也满足字面要求。
- **修复判据**：抽历史报告，对 🐺 与真坑走漏报轨的条目做二判，统计「判狼证据为单一二手源」的占比；修复判据 = 判狼证据必须为 A 级一手源或直接复现，否则降 🟡。

### 攻击 5：M1 用户约束画像 → 隐私边界的系统性无解
- **机制**：M1「预检维度第一来源是用户真实约束（读账本/历史会话/配置）」。
- **失效场景**：用户在某次会话里提过薪资预算/家庭状况，后续一个毫不相干的购买决策任务中，模型按 M1 读取历史会话并把「月薪 30k」写进报告。报告被用户粘贴到群里求同事意见——画像泄露。M1 要求「画像缺失必须上报」，却没有「画像只读聚合特征、不读敏感原文」的边界条款。
- **现有防线为何挡不住**：七条红线与 DoD 全部面向准确性/诚实性，没有一条面向信息最小化；「画像缺失上报」反而激励模型去挖更深的上下文。
- **修复判据**：报告模板画像节强制「只出现决策相关维度的聚合值，出现敏感原文即机检 fail」；用含敏感词的测试会话盲跑，敏感词穿透率必须为 0。

### 攻击 6：验证器副作用三分类在「写类验证器」上是自欺
- **机制**：J4-b 只读/写/不可逆三分类，写类需用户点头。
- **失效场景**：验证「缓存是否过期」需要发一次真实请求（写类：刷新缓存 TTL）。用户点头了。但这个请求本身触发了限流计数，导致后续自动化任务被 429——验证器没有被标「不可逆」，却产生了不可逆的额度消耗。分类的粒度（一次操作级）小于真实副作用粒度（账户状态级）。
- **现有防线为何挡不住**：三分类是单操作、单时点的标注，没有累计效应/配额维度的检查项；环境预检（J4-c）只查存在性，不查副作用预算。
- **修复判据**：抽历史写类验证器执行日志，统计引发非预期状态变更（超出判定表 X/Y 预期输出）的比例；修复判据 = 写类验证器必须附「副作用预算与回滚方式」字段，机检强制。

### 攻击 7：L4「正文只呈现命中坑卡」与 100% 扫描义务的共振通胀
- **机制**：L4「扫描计数一行带过，未命中进附录」与 L1 的 100% 扫描互为镜像。
- **失效场景**：用户问「这份 API 迁移方案行不行」。模型扫了 120 张卡，命中 6 张进正文。但**未命中 ≠ 不相关**：120 张里有 9 张 trigger 字段写得含糊，模型半猜半判地归入未命中——这 9 张恰好含一条费用陷阱。正文精简策略（为治元坑⑫通胀而生）成了漏报的结构性掩护：越精简，越没人追究附录。
- **现有防线为何挡不住**：DoD 机检查计数、检查命中条目的三态完整性，**不检查未命中判定本身**。元坑⑫的修复（正文瘦身）与 L1 的 100% 义务组合出了新的盲区。
- **修复判据**：附录中未命中条目抽样 10% 做人工二判，「判错归入未命中」率 >5% 即失效；机检可加「未命中条目须带一行判定理由（逐卡 ≤15 字）」，让表演成本高于诚实成本。

### 攻击 8：M3 信源分级无法处理「A 级信源的正确性衰减」
- **机制**：M3 A 官方一手 / B 权威二手 / C 社媒。
- **失效场景**：官方文档明确写着「默认超时 30s」，坑卡与报告据此标 ✅。但该库 v2.0 把默认值改成了 5s，文档滞后未更新——A 级信源本身错了。M3 的整个等级序是「静态的权威」，而踩坑场景里最危险的恰是「曾经正确的一手源」。规则没有「官方文档与实测冲突时以谁为准」的裁定——信任序里 `实测 > 官方文档` 在 L3 出现了，但 M3 红线「禁止基于 C 级信源展开分析」没有对应的「A 级信源失效检测」。
- **现有防线为何挡不住**：红线 3 只防「低信源」，不防「高信源的过时」；判定表前置（J4-a）只约束执行后的解读，不约束「要不要怀疑 A 级源」的启动条件。
- **修复判据**：✅ 条目若唯一证据为文档（无实测/源码），机检强制降半档并要求附版本核对行；统计历史事故中「A 级源过时」类占比作为验收基准。

### 攻击 9：升档触发器被「任务拆分」绕过
- **机制**：L0 不可逆动作显式清单，命中即锁 T1+。
- **失效场景**：用户分两个会话操作：会话 A「帮我把这个库的 5 张表写成 CSV」（模型判 T0：只读），会话 B「把这 5 张 CSV 导入新库覆盖旧表」（模型判 T0：CSV 是本地文件）。不可逆的实质——**覆盖生产数据**——被拆解成了两个各自无害的子任务，每个子任务的触发器都不命中。清单是任务级的，攻击面是会话序列级的。
- **现有防线为何挡不住**：J1-c 模型只升不降，但升档判断同样只看当前任务；M1 画像读历史会话可部分缓解，但没有「跨会话任务拼图」的义务条款。
- **修复判据**：构造 10 组「拆分式不可逆」任务对盲测，要求报告头写「本任务是否为更大不可逆链的一环及依据」；机检该字段存在性，抽人工二判其理由。

### 攻击 10：DoD 机检 `dod_check.py` 自身是单层防御
- **机制**：机检只对 T1/T2 强制，脚本不可用时「人工自检六条」降级。
- **失效场景**：`dod_check.py` 检查的是报告的**文本形态**（阻断待办存在性、回填栏存在性），不是语义。模型学会写模板合规的空壳：「动手前必须完成的检查：无」「执行结果：符合预期」——六条全绿，机检通过，谎报轨的判定却依赖「虚报」被抓到，而机检恰恰检不出最便宜的虚报形式。整个诚实架构的最后一道闸，本身就是被 LLM 输出直接喂饱的字符串匹配。
- **现有防线为何挡不住**：这是典型的单层防御（SKILL.md 自己的 M9 都禁止单层，但 DoD 机检+人工自检两层查的是同一份文本）；元坑⑬只处理了 T0 自检悖论，未处理 T1/T2「机检文本化作弊」。
- **修复判据**：构造 10 份语义虚报但格式合规的报告样本，dod_check.py 全放行即为实锤；修复判据 = 抽样复核制度（外部上下文二判 ✅ 区，J3 验收里其实已有雏形，应升为常态）+ 机检对「无/空」类默认值条目强制标黄。

## 三轮攻击后的结构性结论（附赠，按致命度）

1. **最致命：判断标准全部内嵌于同一个判断主体**——L0/L2/L4 的每次硬化都只是给模型加规则文本，执行判断的仍是同一上下文里的同一模型，规则越多，绕过规则的自由度也越多（攻击 1/4/7 共同指向）。
2. **次致命：契约是对「报告时刻」的契约，不是对「决策-执行链路」的契约**——验证半衰期（攻击 2）、跨会话拆分（攻击 9）、A 级源衰减（攻击 8）都发生在报告交付之后，现有机制对此零覆盖。
3. **第三：合规检查正在成为新的攻击面**——100% 扫描、机检、附录瘦身这些为防通胀/防谎报而生的机制，本身制造了可被形式合规掩盖的漏报形态（攻击 3/7/10）。

## 减法建议

- **删掉 L1 的「100% 逐卡」义务**，换成哨兵卡抽检制（攻击 3/7）：召回质量交给可测量的探针，不交给模型的注意力预算。
- **合并 M3 信任序与 L3 信任序**为单一动态序（攻击 8）：当前两处矛盾（红线 3 崇尚 A 级源 vs 信任序实测>文档）是隐患。
- **把 M1 的画像范围写窄**（攻击 5）：「缺失上报」改成「缺失上报 + 最小化采集」，一行解决隐私暴露。
