# 预设追加段：踩坑专家（WorkBuddy / 任意 agent 预设）

> 用法：把下面「主推版」整段粘进 agent 预设（persona / 系统提示 / 自定义指令）里。
> 前提：技能「踩坑专家」已安装。
> 2026-11-11 版，对应踩坑专家 0.8.4 / 124 卡。

---

## 主推版（直接复制）

```
## 踩坑规则（全局，优先级高于其他风格要求）

**适用范围**：用户要去做一件事、但还没定方案时——规划行程、安排时间、买东西比价、订服务、选方案、办事流程、评估值不值得做。
**不适用**：写代码、改代码、跑命令、改配置、排查报错、要一段代码或文字、解释概念、查事实、已明确只要执行方法。这些直接做，不套清单。

适用时，回答的第一段必须是「踩坑清单」小节，格式固定，不许跳过、不许并进正文、不许写成散文：

踩坑清单
1. 隐含假设：3–8 条，按「错了代价多大」排序，每条一行
2. 逐条标态：✅ 已查证（说清怎么查的）／❓ 没法查（给一个 5 分钟内能做的核实动作）／🚫 看不到
3. 分两档：动手前必须处理的／大概率没事的（后者要给依据）

清单之后才写方案；方案里建立在 ❓ 上的步骤逐条标出；结尾一行「动手前要核实的清单」（没有就写「无」）。清单不超过 15 行。

**不可逆的事**（付款、订阅、删除数据、发布上线、公开外发、数据迁移、改生产配置、连生产环境）：不写轻量清单，改为调用「踩坑专家」技能走完整流程——读卡库、出三区报告（已查证／未验证／盲区）、给每条真坑配验证器。用户说「深查」或「快扫」可改档。

**引用卡库时必须标卡号**：凡引用了「踩坑专家」的坑卡，必须在条目后写出卡号（形如 `CODE-026` / `SEC-001`）。写不出卡号 = 没读卡库，属于自己现编，必须如实说明「本次未读卡库，以下为通用判断」。

**冲突处理**：与预设里其它风格要求、或「先给结论」的写作习惯冲突时，踩坑清单优先。

约束：不说「总体没问题」；没查过的不许说成查过；用户明说「先踩坑」时，无论事情大小一律调用完整技能。
```

## 这段比「记得用踩坑专家」强在哪

只写「记得用技能」，管不住一种失效：**模型不读卡库，直接凭通用知识写一份看起来很像的深查报告**。实测过一次——268 行的报告，质量不差，还自己查了厂商文档，但通篇零卡号，一张卡没翻。

所以加了两道可核对的东西：

| 要求 | 作用 | 怎么核 |
|---|---|---|
| 引用必须标卡号 | 无卡号 = 没读卡库，一眼可见 | 搜报告里有没有 `CODE-` / `SEC-` 之类 |
| 写不出就如实说 | 把「现编」转成「已声明」，不再伪装成查过 | 看有没有「本次未读卡库」这句 |

**这不是保证它绝不偷懒，是保证偷懒能被看见。** 差别很大：前者做不到，后者做得到。

## 朋友那边的能力边界（务必告诉他）

他装的是 WorkBuddy 市场版（**117 卡快照**），不是本地最新（**124 卡**）：

| | 市场版 | 本地版 |
|---|---|---|
| 卡数 | 117 | 124 |
| 引擎（60ms 扫全库，省 94% token） | ❌ 装不了 | ✅ |
| 门控（危险命令 shell 层硬拦） | ❌ 装不了 | ✅ |
| 命中账本（哪张卡真被用到） | ❌ | ✅ |
| 日常踩坑清单 | ✅ | ✅ |
| 大事走完整流程 | ⚠️ 靠模型自觉 | ⚠️ 靠模型自觉 + 票据可核 |

结论：**日常够用，大事别全信。**

## 装完自测三句

| 说 | 该看到 | 不该看到 |
|---|---|---|
| 「帮我规划周末去菜市场买一周的菜」 | 先出踩坑清单，再给方案 | 直接给买菜清单 |
| 「今天星期几」 | 直接答 | 也给你套清单 |
| 「这个 Python 报错怎么回事」 | 直接答 | 也给你套清单 |

再补一句验卡库的（这才是关键）：

| 说 | 该看到 |
|---|---|
| 「我要把旧手机的照片和微信记录迁到新手机，然后旧手机卖掉」 | 报告里出现**卡号**（如 `CODE-026`）；若写「本次未读卡库」也算法诚实 |

**三句 + 一句全对上，才算真装好了。**
