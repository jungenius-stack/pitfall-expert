## 二、账本和票据实际改了什么

- `engine/src/scanner.js`：新记录 schema 2 默认仅含 `ts/ticket/source/tier/domain/taskHash/hits` 及 schema 标记；`hits` 仅 `id/score`。默认无任务 `task` 和触发词 `trig`。
- `taskHash` 为完整传入扫描器任务的 SHA-256，保留其空白；CLI/MCP 原有输入规范化仍存在。它用于本机匹配，**无盐、非匿名化、非签名，仍可被猜测或关联**。
- `PITFALL_LEDGER_TASK=on` 才额外保存前 60 个 UTF-16 码元，字符串 `true` 不算开启；`PITFALL_LEDGER=off` 优先，关闭记录与票据。没有修改本机环境设置。
- 新建账本目录/文件分别指定 0700/0600，既有权限和旧记录不动；没有宣称解决既有权限、符号链接或其他客户端日志的全部安全边界。
- 追加失败仍返回扫描结果，`ledgerStatus=failed`，不保留不可核对票据；报告明说失败，不再写“已同步入账”。无票不能单独推出“没跑”。
- `tools/verify-ticket.mjs`：新记录须完整任务摘要匹配，旧记录仅精确匹配原有前缀并警告；只给票、不提供任务、同票多行、坏摘要或未知 schema 均拒绝。输出不回显任一任务原文。文件模式只认唯一、相邻的引擎元数据头，遇歧义拒绝；手写/改写报告可改用显式票据加完整任务。命令行原文仍可能进入 shell 历史/系统进程信息。
- `PRIVACY.md` 双语、两份 README、hooks/dsh 说明和 SKILL 票据规则对齐实际边界：**引擎账本不存原文，不等于整套 AI 客户端不留原文**；正常报告仍含任务，独立 hook 日志默认关但开启后仍有最多 200 码元输入前缀，dsh logger 另算。
- MCP 的 `readOnlyHint` / `idempotentHint` 改为 false，承认默认本地追加；不因测试关闭账本而继续对客户端声称默认只读。`package.json` 白名单补入验票工具，避免 npm 包中找不到它。

票据校验只核对本机记录对应范围，不证明账本未被编辑、引擎执行不可伪造、卡已读懂、验证器已执行或任务正确。

## 三、三卡怎样纠偏

| 卡 | 已实施 | 为何这样改 |

三卡的 description / symptom / evidence / fix / verifier / falsification 已互相对齐；verifier 仍是**给调用方执行的文字判定表，不是已实现并实测的服务检测器**。保留正常、异常、证据不足三种结果边界，以及动态测试另批授权、独立资源预算和停止清理路径。

卡数仍 124。与 HEAD 的 YAML 对象逐项比较：其余 47 张 code 卡未变，三卡原触发词、severity、confidence、pass_k_relevant 未变；其他六份卡文件未修改。个人案例前缀元数据仍 13 张。撤去 050 parent 后，全库当前无 parent 字段，不能再声称有已投入运行的子卡，也没有新增母子联动或家族统计。
