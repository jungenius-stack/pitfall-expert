# 交付物 1：现成方案调研报告

> **调研问题**：业界是否已存在满足「踩坑专家」需求的现成方案——AI 任务执行前的通用坑点预检能力？
> **调研日期**：2026-10-15。调研渠道：GitHub（API + raw 文件抓取）、WebSearch、WebFetch、AMiner/arXiv。
> **本报告自身的检索边界声明**（预先示范「踩坑专家」要求的披露规范）：检索完成于 2026-10-15，此后的新项目未覆盖；搜索接口多次限流（429），部分候选仅能以「未核验」收录；capafy.ai 两次访问均 403（反爬），其存在性仅有二手来源。详见第六节。

## 一、需求判据（什么叫「满足需求」）

「踩坑专家」的目标能力拆为四条硬判据，任何方案四条全中才算「现成答案」：

| # | 判据 | 说明 |
|---|---|---|
| J1 | **任务执行前预检** | 在正式动手前挖坑（常见错误、隐含前提、易错环节、工具链/环境问题、事实性陷阱、逻辑漏洞），而非运行时输出防护或事后测试 |
| J2 | **分领域坑位库** | 预沉淀、可扩展的领域坑位清单（数学/科学/代码/创意/调研决策…），不是每次靠模型现场发散 |
| J3 | **验证披露** | 输出区分「已验证/未验证/盲区」，每条坑带证据链，用户无需靠质疑来质检 |
| J4 | **跨 harness 可复用** | 至少覆盖 dsh（DeepSeek harness）+ 一个主流外壳（Claude Code / Codex / ZCode 等），可开源分发 |

## 三、差距分析

### 3.1 外部生态：四条判据全中的方案 = 0 个

- **J1（任务前预检）已成熟**：Klein pre-mortem 框架的 prompt 化是红海，36+ 个同质化 skill。
- **J2（分域坑位库）全体缺失**：所有 premortem skill 靠模型现场发散；唯一分域素材 awesome-falsehood 是人读清单、无预检流程、无触发机制；最接近的 AndyShaman angle-pool 是「视角池」而非「坑位库」。
- **J3（验证披露）接近空白**：parcadei 的 Verify Before Flagging（要求每条风险附验证证据，否则不许报）是目前最接近的机制，但它用于防误报，**没有任何项目输出「已验证/未验证/盲区」三态披露**。
- **J4（跨 harness）无人做**：PreMortemX 绑死 Codex，其余绑死 Claude Code；SKILL.md 虽是纯 Markdown 理论可跨，但无项目做双端适配发布。

### 3.2 对 v0.2 既有稿的差距分析（按用户决策：独立设计、显式对比）

v0.2 已具备的（应予承认）：三区输出契约（✅已查证/❓未验证/🚫盲区，且强制「空区也要显式写空」）、DoD 五条过程标准、服务档位（快扫/标准/深审）、SOP 4 步、元坑登记簿、「漏报可原谅、谎报不可原谅」判据、坑库自举条款。**它在 J3 上是全部方案中最完整的。**

v0.2 的差距：

1. **未通过自举验证**：v0.2 自己在第 9.4 条承认「尚未经过真实任务回放验证——它还没通过自己的 DoD」。10 条坑点案例回放（见《坑点案例库 v1》）尚未执行。
2. **J2 缺失**：无任何分领域坑位库实体，仅有「按领域扩展」的框架意图；坑卡条目规范有了，坑卡本身一张没有。
3. **形态未落地（J4）**：skill vs dsh 插件的选型明确留白，未验证 dsh 的实际扩展机制。
4. **证据强度标注不一**：如「+30%」等引述在 v0.2 内已自我降级为方向性，但仍有个别机制（如「激活率低至 ~20%」）来源不明，需在实现前逐一核验或降级。
5. **触发机制未设计**：何时、如何被调用（自动/手动/挂载点）没有落到具体 harness 机制上。

### 3.3 学术侧交叉验证（与交付物 2 互证）

A2/A4 两个子代理独立得出一致结论：**「任务开始前 + 面向通用任务 + 结构化（清单×假设映射×多层防御×外部验证）」的预检方法论在学界同样空白**。最接近的工作是 *Before Agents Speak*（arXiv:2607.26836，多智能体故障预定位）与 SafetyDrift（arXiv:2603.27148，执行中违规预测），均为 2026 年新出且不覆盖通用任务预检——窗口存在但在收窄。

## 四、结论

1. **没有现成答案**：外部 15 项 + 内部 v0.2，四条判据全中者为零。「踩坑专家」要做的是**组合创新**，不是重复造轮子。
2. **组装件已备齐**（这是最有利条件）：Klein 回推框架（公共底座）+ Tiger 三分类（防清单通胀）+ Verify Before Flagging（升级为三态披露）+ awesome-falsehood（坑位库底料）+ 脚本/LLM 分工原则 + hook 触发机制——全部有成熟先例可借鉴。
3. **差异化护城河**：①分领域坑位库（唯一）②三态披露契约（业界最完整）③坑库回写闭环（美团 COE 式相似召回）④真实翻车案例回放验收（10 条一手考题）。
4. **风险提示**：premortem skill 是同质化红海（36+ 个），开源后真正决定成败的是 J2/J3/J4 这三块没人做的苦功，而非 prompt 模板本身。
