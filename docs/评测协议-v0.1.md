# 效果评测协议 v0.1（设计稿——2026-10-16，v0.7 后最高优先级）

> 要回答的唯一问题：**装了踩坑专家，到底拦住了多少坑、付出了多少摩擦？**
> 当前所有验证都是自举（自己出题自己答），本协议是第一套外部可复核的效果测量。
> 双评审共识：红队弱点一/二/三与沉思结构结论 1/2/3 的根治全指向本协议——没有测量，"改进"只是猜测。

## 一、测试集构建（eval/tasks/*.yaml，与 cards/ 分库隔离）

- **规模**：≥40 个任务，六域各 ≥6，加 ≥4 个跨域复合任务；三档难度（T0/T1/T2 各三分之一）
- **来源纪律**：任务描述不得复用任何卡库卡的症状/触发词原文（防背题）；每任务附标注「应命中卡 ID 清单 + 应判档位」，标注人 ≠ 出题人
- **哨兵卡机制**（沉思攻击 3 的修复判据落地）：评测模式额外加载 3–5 张哨兵卡（trigger 与测试任务强匹配、内容明显可辨）。**哨兵命中率 = 100% 扫描义务是否已形式化的直接测量**——命中率随卡库增长下降即实锤
- **反作弊样本**（沉思攻击 10）：手工构造 10 份「格式全合规、语义虚报」报告（如 动手前检查：无／执行结果：符合预期），机检全放行即证明机检语义盲区，抽查制度必须存在

## 二、指标

| 指标 | 定义 | 合格线（v1 起点） |
|---|---|---|
| 漏报率 | 应命中卡未被命中 / 应命中总数 | ≤15%（宁漏报不错报取向） |
| 误报率 | 命中卡与任务不相关（人工二判）/ 命中总数 | ≤10% |
| 哨兵命中率 | 哨兵卡被正确召回 / 哨兵总数 | =100%（低于即 100% 义务形式化实锤） |
| 域判定准确率 | 自动判定域 = 标注域 | ≥85% |
| 摩擦成本 | T0/T1/T2 各档扫描耗时 + 报告行数中位数 | T0 ≤10 行、T1 ≤60 行、T2 不设限但记录 |
| 阻断有效率 | 阻断待办被执行且确实拦下问题 / 阻断待办总数 | 记录基线，v2 再设线 |

## 三、基线对照（同一测试集跑三臂）

1. **A 裸跑**：无预检直接执行任务，事后按标注清单数踩坑数
2. **B 纯提示词**：只贴入门版（docs/入门版-贴即用.md）
3. **C 完整版**：技能+引擎全流程

报告 A/B/C 的踩坑数差 = 技能的真实拦截量；B/C 差 = 卡库与验证器的边际价值。

## 四、执行与裁决接口（测完必须做的决定）

- **语义匹配是否上**：若漏报主因是词形/同义未命中（非任务超出能力表），可试第二层匹配；前置判定表：跨域误命中不增（元坑⑰程序复用）
- **100% 扫描义务是否改抽检**：哨兵命中率连续两轮 =100% 且稳定 → 可讨论；<100% → 义务保留并修扫描方式
- **机检是否加语义层**：反作弊样本全绿 → 建立人工抽查制度（外部上下文二判 ✅ 区，每 10 份抽 1）
- **档位摩擦是否超标**：摩擦成本超线 → 先砍报告模板行数，不动机制

## 五、防污染与复跑

- 评测集永不入库为卡；哨兵卡只存在于 eval/ 目录（loadCards 用 `cardsDir` 参数加载，已有接口）
- 全指标跑两轮取一致性（pass² 思想：两轮结论方向不一致 = 任务集不稳，先修任务集）
- CI 只跑 quick 冒烟（哨兵 3 张 + 域判定 10 任务），全量评测手动触发

## 六、诚实边界

- 本协议测的是「已知坑的拦截率」，测不了 unknown unknowns（公理 1）——拦截率 100% ≠ 安全，只等于「对已建卡的坑有效」
- 人工二判引入主观性：二判人固定且记录判定理由，争议条目进 ❓ 不计入误报
- 40 任务是最小可信规模而非统计充分规模；指标只用于方向性裁决（上/不上/改/不改），不用于对外宣传百分比
