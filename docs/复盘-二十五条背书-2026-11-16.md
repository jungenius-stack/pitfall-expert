## 二、判定口径

将三个问题分开，不能用一个“已验证”包办：

1. **来源层**：论文/事故/文档存在、这次实际取到了什么？页面 200、引用列表有链接、先前报告写过“亲读”，均不等于本轮读过原文。
2. **主张层**：证据直接支持卡的哪个机制？“直接支持部分主张”不等于整卡的所有机制、频率、严重度与规避动作均得到验证。
3. **外推层**：是否跨越了研究对象、任务、时间顺序、数值定义或因果方向？方法建议及诊断启发式不自动变成事故实证或充分必要判据。

下表“对口程度”专评 **新增 endorsement 对卡上机制的关系**；原 source 的独立支持单列在“关键限制”，避免用新背书的不足抹掉原证据。四档为：直接支持部分主张／仅邻证／不对口／未核。未取到全文的项目只写“摘要/片段/原页未取到”，不称“已证实”。其中数学项的形式推演或算术复算是独立论证，不冒充历史文献核验。

建议的含义：**保留**＝可保留其有限证据用途，不等于原文每字都准确；**收窄**＝对象、措辞或用途应缩到证据范围；**暂缓升级待核**＝不足以用此背书维持此次升级理由，应交用户重新裁决，不代表本轮自动回退字段。

## 四、六项重点：本轮到底取到了什么

### 1. CODE-015：goto fail 只能证明漏洞，不能证明“顺手范围外多改”

- 指定 NVD 入口：<https://nvd.nist.gov/vuln/detail/CVE-2014-1266>，本轮被 Cloudflare 拦截，未取其正文。
- 官方替代：<https://cveawg.mitre.org/api/cve/CVE-2014-1266>，取得完整 CVE JSON，Apple CNA 描述关键句为 **“does not check the signature in a TLS Server Key Exchange message”**。
- 这能证明验证缺陷；记录没有原任务范围、提交授权、作者动机或重构上下文。代码“多一行”也不是项目需求“多改一项”。不能从漏洞形状推出范围蔓延因果。
- 原 source 的 Karpathy 倡议及“只移动却改语义”案例没有因此失效，但其具体任务/补丁须另核。本轮只否定用 goto fail 补齐该因果桥梁，不裁撤整卡。

### 2. CODE-038：位置效应有实证，逐跳衰减另有定性来源

- 官方摘要：<https://arxiv.org/abs/2307.03172>；取得标题、作者与完整摘要，**未读论文全文**。研究任务是 **“multi-document question answering and key-value retrieval”**，结论为相关信息在输入开头/末尾时表现通常最高，中段更差。
- 因而它能支撑“长上下文中段信息不易有效利用”，不能直接推出多 Agent 链长每增加一跳保真度下降，也不能证明重申约束、传全文或持久化文档的因果效果。
- 原 source 追溯后，本轮取得 Splunk 对口段落：<https://www.splunk.com/en_us/blog/artificial-intelligence/multi-agent-system-failures.html>，原句 **“Sequential chains compress earlier messages, eroding information fidelity with each hop.”**；MLM 对口段落：<https://machinelearningmastery.com/building-ai-agents-here-are-some-anti-patterns-to-avoid/>，说明上下文 token 增长时回忆能力下降及旧数据过时。
- 所以此卡不是“无来源”；应把“厂商/工程方法性论述”与“控制位置的学术实验”分开引用。这里没有逐跳受控实验、损失曲线或某个最新模型的统一失效率。

### 3. CODE-005：Knight 官方原令未取到，不能用熟悉的事故替代核查

- 官方原令：<https://www.sec.gov/files/litigation/admin/2013/34-70694.pdf>，403；官方新闻 <https://www.sec.gov/newsroom/press-releases/2013-2013-222htm> 超时，<https://www.sec.gov/news/press-release/2013-222> 403。本轮**未取得官方事故正文**，不把工具最初“PDF 不支持”的错误算作已读。
- 未取到不等于 Knight 事故是假的；意思是本轮不能重新背书其数额、时长、部署细节，更不能凭转述认定“每步任务检查点”就是经事故验证的充分规避措施。
- 原 source 的 MAST：<https://arxiv.org/abs/2503.13657>，取得官方完整摘要，提到 1600+ traces、7 个框架、14 类失败及 task verification 等类别，**不能从摘要推出 CODE-005 特定动作的干预效果**；OWASP ASI08 未取得对应原文。
- 待核的具体桥梁应是：哪个中间状态错误、传给哪一步、哪一个可实施检查能够及时截断；部署一致性核验、自动交易限额、告警响应与通用 Agent 检查点不是同一个验证器。

### 4. RD-019：计划“草案之后”不等于执行“之后”

- HBR：<https://hbr.org/2007/09/performing-a-project-premortem>，取得摘要和免费首段，页面其余正文受限；不能写“全文亲读”。首段支持在 planning phase 鼓励异议，但不证明必须在第一份计划出现之前。
- Gary Klein 作者官网：<https://www.gary-klein.com/premortem>，免费取得方法介绍原文。关键句为 **“A Pre-mortem is an exercise that typically begins after a team has been briefed on a plan.”**
- 精确区别：可以先有**待挑战的草案/拟议计划**，再假设失败、找任务特定弱点、修改计划，在**定稿和执行前**发挥作用。卡面却把“计划生成前”写成硬边界，把之后一概等同装饰；这并非经典 premortem 的必要顺序。作者页也不是“所有场景唯一正确时点”的实验。
- 原 source 的 Capafy 是更严格的 AI 工作流倡议，不等同 Klein 原方法；本轮 <https://capafy.ai/agent/pre-mortem-planner/5575019543> 返回地区不可用 403。parcadei 的核查清单、Nemeth 关于真实异议与扮演反对者的研究，即便各自成立，也不直接测试“首份草案之前还是之后”的比较。
- 可保留的核心：风险要具体、可查、能改变计划，缓解要可执行；不能仅按出现于草案前后就裁定有效/装饰。建议重审“铁律”和以方法文升 `case` 的理由，不是宣判整卡无效。

### 5. SCI-004：过拟合不等于在信号时读取未来价格

- 刊方 PDF：<https://www.ams.org/notices/201405/rnoti-p458.pdf>，本轮 403 验证页，**未取得所挂刊版 PDF**。
- 通过 Crossref 元数据（DOI <https://doi.org/10.1090/noti1105>）及作者论文目录，取得作者自存预印本：<https://www.davidhbailey.com/dhbpapers/backtest-pseudo.pdf>，2014-04-01 版本，34 页。作者为 David H. Bailey、Jonathan M. Borwein、Marcos López de Prado、Qiji Jim Zhu，不能让“两位作者简称”造成只有两位作者的印象。
- 亲读摘要、定义与方法相关页；摘要第 2 页：**“The higher the number of configurations tried, the greater is the probability that the backtest is overfit.”** 第 3–4 页区分样本内/样本外，举用历史样本反复调参的例子；第 14 页另讲终止表现差基金带来的 survivorship/selection bias。
- 对该预印本完整提取文本做有限词检，未见 `look-ahead`、`leak`、`repaint`；这只是检索辅助，不是“证明全文绝无相关思想”。关键在于读到的研究设计是多配置选择与过拟合，**没有据此建立卡面当根收盘信号/当根成交、重绘、全量归一化泄漏的具体实证**；未比较刊版与预印本逐字差异。
- 原 source 本来就列了 Pine Script 官方生态与其他量化案例，不应丢掉。TradingView <https://www.tradingview.com/pine-script-docs/concepts/repainting/> 本轮连接重置，其他原文未取；应另核信息可得时间、重绘类型和执行假设。“信号移一根后收益变了”只能提示时点敏感，**不是泄漏的充分证明**；“永远赚钱”也不是泄漏必然后果。

### 6. SCI-005：医生误读 PPV 不等于分类器召回为零

- PubMed 页面触发 cookie 验证，NCBI efetch 连接重置；转 EBI Europe PMC 官方 MED 记录取得题名、作者、DOI、PMID 与完整摘要：<https://www.ebi.ac.uk/europepmc/webservices/rest/search?query=EXT_ID:26161749%20AND%20SRC:MED&format=json&resultType=core>。
- 题名 *Helping Doctors and Patients Make Sense of Health Statistics*，PMID 26161749，DOI <https://doi.org/10.1111/j.1539-6053.2008.00033.x>。**本轮未取得全文**；API 标记全文 Subscription required。DOI/PMID 相符只证明身份，不证明具体“多数医生/99%”表述已核。
- 摘要主张为健康统计素养缺失、风险框架误导及自然频数沟通，不是多数类分类器的 accuracy/recall 实验。敏感度、特异度、总体 accuracy、PPV 不能统称“99% 准确”后互换。
- 原 source 的 dummy classifier 教程/实例与卡的机制更直接，只是本轮没有重新取其全文与 99.83%/97.5%/250 例的原始数值。独立反例则无需查事故：10 万样本中有 1000 阳性，全报阴性，则 TP=FP=0、FN=1000、TN=99000，accuracy=99%、recall=0；阳性率 0.1% 时 accuracy=99.9%、recall 仍为 0。precision 的分母为 0，应记未定义或声明实现约定，不能偷写为已测 PPV。
- 因而可保留“accuracy 不足以评价稀有正类识别”的结论，但不把这篇论文算作零召回模型案例，也不把“模型不比 dummy 高 2 点”当成已标定的通用有效性阈值。

## 五、前三个应优先修的：具体修什么，不自动执行

1. **RD-019：先修会误判正常工作流的铁律。** 作者原文已有直接时序证据。拟将“风险必须早于任何计划生成”收为“拟议计划在定稿/执行前接受具体失败推演，结果必须能反过来修改计划”；保留反装饰核心。Capafy 可作为一种更严工作流的出处，不能代称经典 premortem 的普遍实证结论。最终是否改 `case` 交用户裁决。
2. **CODE-015：撤掉没有证据的事故动机/授权归因。** goto fail 可以保留为漏校验的真实漏洞背景，不再写“范围外多一行”。用原 source 的“仅移动任务却改变行为”补齐实际约束、diff、复现结果，才是范围蔓延的对口案例。另将 whitespace diff 从“语义偷改充分判据”收为审查信号。
3. **CODE-038：拆开三种机制，避免实证借壳。** 新论文标清“长输入位置效应”；逐跳压缩与漂移保留其原 source 的定性支持身份，不借论文名把它们都升成受控实证。没有必要为纠正证据口径就拆卡/新建卡，也不在本轮替用户定字段。

SCI-004、SCI-005 为下一梯队：前者需要前视可得性/重绘的对口原证，后者应让数学反例和已有 dummy classifier 来源直接承重，不用医生统计素养实验充当替身。并非排在前三之后就可放任其升级理由不审。

## 六、endorsement 目前是否进入报告

**结论：在当前 `engine/src/report.js` 的标准文本报告与反馈包中不展示。** 这是静态源码核查，不是本轮跑引擎得到的票据。

- `engine/src/report.js:28–43` 的 `cardEntry()`：第 33 行只输出 `c.evidence.source` 与 `c.evidence.level`，接着输出规避动作、置信度、命中依据和复跑提示；无 `endorsement` 字段。
- 同文件第 86–89 行的未验证区只列标题、原因和验证器；第 166–195 行 `buildFeedback()` 也不展示 endorsement。因此升成 `case` 的标签可见，导致该升级的新增证据和限制却不可见。
- `engine/src/scanner.js:301–303`：进 verified/unverified 取决于卡级 `confidence`，不是运行时核读来源，也不是 endorsement 的存在/相关性，更不是 `case` 标签。改 level 不会自动改变这条分区逻辑。
- `loadCards()` 对卡对象保留字段，并不等于文本报告会渲染这些字段；本结论也不扩大成“任何外壳、任何 JSON/API 输出都绝不包含 endorsement”。本轮没有做各端同步包的逐项展示复测。
- 因此，“报告不显示新增背书”确实成立，但不能以此反推卡没有原证据，或未经用户同意就把背书合并进 `source`。是否增设显示及如何呈现限制，另行裁决。

## 七、给用户的有限裁决选项

- **可接受的当前表述**：“25 张卡补挂了出处；本轮逐项区分直接部分支持、邻证、不对口和未核。原 source 与新增背书分开承重，数学反例有独立价值。”
- **不可接受的表述**：“25 张全验真”“有链接就是事故实证”“123 张全是有效背书”“一旦免死就不必再审”“已读到摘要，所以所有数字和因果都已核”。
- `case`/`empirical` 是证据类型标签，不是有效性章；方法倡议不能仅因有名人出处就变事故个案，理论反例也不能仅因没有事故就被判无效。若不另设数学/官方行为等类型，至少应在证据文字中说明类型与覆盖范围，是否调整 schema 不在本轮决定。
- 待核优先取**能改变裁决的原句/段落或可复算数据**，而不是继续堆链接。修补背书后仍须复审关键数字、因果链、域外推、验证器阈值与适用条件；来源真实不是永久免审条款。

本轮到此只交裁决材料，不改卡、不改评级、不改展示逻辑、不提交。卡级升级/回退、免死规则及前三项具体改法，均尚未获得本轮用户裁决。
