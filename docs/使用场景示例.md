# 使用场景示例（v0.3）

> 每个例子 = 用户原话 → 踩坑专家抓到的坑（真实坑卡编号）→ 验证器清单 → 躲过什么。
> 所有坑卡均可在 cards/ 目录核对；标 🔴 的为深审档高危项。

## 一、重度 AI 编程的人（Claude Code / Codex / WorkBuddy）

### 例 1：“测试都绿了，提交这个 bug 修复”
- 抓到：**CODE-004 测试通过≠正确**（实证：7.8% “通过”的 patch 实际错误，29.6% 与预期行为分歧）+ **CODE-015 顺手过度修改**（实测该任务描述还会弱命中 CODE-017/018——靠“测试”等通用词字段重合，报告里逐条列出命中依据，用户可当场折扣）
- 报告会说：测试全绿只证明“没抛异常”，不证明“行为正确”——请审查测试断言的是行为值还是仅不报错。
- 验证器：① 审查测试断言强度（是否断言行为值而非仅存在性）② 对边界/对抗输入跑一遍 ③ 完成后运行状态断言脚本比对“预期 vs 实际”。
- 躲过：把没修好的 bug 标成 fixed 合进 main，三周后生产环境炸。
- 复现命令：node engine/src/cli.js "bug 修好了，测试都绿了，帮我提交这个修复" --tier quick

### 例 2：“升级 lodash 到最新版，顺手清理没用的代码”
- 抓到：**CODE-007 死代码/遗留配置重新激活**（Knight Capital：一个遗留 flag 45 分钟损失 4.4 亿美元，SEC 行政命令可查）+ **CODE-012 版本区间漂移**（^1.2.3 某天装到 1.9.0 就挂）+ **CODE-015 顺手过度修改**
- 报告会说：删除“无人引用”的代码前必须全仓 grep；“顺手清理”是范围蔓延的高发形态。
- 验证器：① 变更前输出全仓引用 grep 报告并逐条确认 ② lockfile 一致性检查 ③ 提交前 diff 逐文件对照需求清单。
- 躲过：删掉一个“没人用”的工具函数，结果它被三个动态 require 的角落引用，升级当天全线报错。

### 例 3：“把这 500 个用户上传的文件批量重命名”
- 抓到：**CODE-010 路径/Unicode/编码**（NFC/NFD 归一化、中文路径、超长路径）+ **CODE-013 空值与边界**
- 报告会说：macOS 的“看起来一样”的文件名，字节层面可能不同；空文件名/单字符名/超长名是三大杀手。
- 验证器：构造 NFD/NFC/中文/空格/超长/空文件名测试集跑一遍读写与匹配。
- 躲过：重命名脚本在测试目录一次成功，上生产后 30% 的文件“找不到”——因为真实用户传的是 NFD 编码的中文名。

## 二、用 AI 做数学证明、数据分析、统计的人

### 例 4：“证明：对任意正整数 n，n³−n 能被 6 整除”
- 抓到：**MATH-001 循环论证** + **MATH-002 逆命题混淆** + **MATH-007 逻辑跳跃**（“显然”跳过关键步）
- 报告会说：证明动笔前先写“前提清单+目标”两张表；每步只许引用清单内条目；把原命题/逆/否/逆否四形式写出并标明要证哪个。
- 验证器：① 前提-步骤-结论追溯表（逐步标注依据）② 四形式对照表 ③ 遮住每个“显然”步骤尝试一步复现，失败即缺口。
- 复现命令：node engine/src/cli.js "证明：对任意正整数 n，n 的立方减 n 能被 6 整除" --tier quick（实测命中 MATH-001/002/004/007 四张证明卡）
- 躲过：AI 给了一份“证明”，实际第 3 步偷偷用了结论本身——交作业/发论文前被抓出来。

### 例 5：“这批实验数据 p<0.05，说明新药有效吧？”
- 抓到：**MATH-012 统计推断误用**（p 值误读、多重比较未校正、相关当因果）+ **MATH-011 概率直觉陷阱**（基率谬误）
- 报告会说：p<0.05 不等于“为真”，更不等于“效应大”；多次检验取显著的那个是自欺；分析计划应前置（预注册思想）。
- 验证器：① 分析计划 vs 实际报告逐条对照 ② 效应量与置信区间是否报告 ③ 偏差审查清单（选择/测量/幸存者偏差）。
- 躲过：把“不显著”的次要指标和显著的主要指标一起汇报，制造虚假信心——顶刊复现危机里最常见的中招方式。

### 例 6：“用牛顿法求这个方程的根，写个程序”
- 抓到：**MATH-009 运算前提失效**（导数零点、除零、定义域外取值）+ **MATH-010 数值稳定性**（迭代无收敛判据、灾难性抵消）
- 报告会说：每个除法/开方前显式声明前提；迭代必须带容差与收敛判据，不能只设步数上限。
- 验证器：① 前提声明清单（每个限制运算一条前提）② 病态输入对比测试（近重根/大导数）③ 收敛曲线审查。
- 躲过：程序在正常输入下完美，遇到导数为零的初值直接除零崩溃，或者“跑完 1000 步”但其实从来没收敛。

## 三、跑长任务 / 多 AI 协作的人

### 例 7：一个 12 步的 ETL 管道（抽取→清洗→关联→聚合→落库→对账……）
- 抓到：**CODE-005 级联失败无检查点**（OWASP Agentic Top 10 的 ASI08）
- 报告会说：多步任务中一步错误向后传播且中途无检查点拦截，错误到终点验收才暴露，前段成果已被污染。每步设检查点（中间状态落盘/断言），失败即停。
- 验证器：每步结束后运行检查点断言，失败时中止流水线并报告断点位置。
- 躲过：第 3 步的清洗逻辑把空值填成了 0，一路带到第 11 步的对账，三小时后才发现全线数据错了 40%——有检查点的话第 3 步就停。

### 例 8：“这个脚本昨天跑成功了，部署上线吧”
- 抓到：**CODE-003 复跑不一致**（实证：单次成功率约 60%，连跑八次全对低于 25%）
- 报告会说：一次性成功被当作稳定性证据，是 AI 时代最高频的自欺。关键任务必须复跑比对。
- 验证器：同输入连跑 ≥3 次，对输出做结构化 diff，统计一致率；报告一致性而非单次结果。
- 躲过：把一次幸运通过的任务排进生产定时器，然后以 30% 的概率周期性产出错误结果，查两周查不到根因。

## 四、小团队（共享仓库 + AI 代理）

### 例 9：新人让 AI“清理一下构建目录”，AI 执行 `rm -rf ./build && rm -rf /tmp/cache`
- 门控（block 模式）：**破坏性命令硬拦截**——rm -rf 模式命中，exit 2 阻断，附完整踩坑报告回给模型。
- 人工确认后才放行；想改成只报告不拦，一个环境变量切换（PITFALL_HOOK_MODE=report）。
- 躲过：AI 把 `rm -rf $PROJECT_ROOT/`（变量为空时）执行成删库——这类事故在 AI 代理进生产的第一年已经批量发生。

### 例 10：某人让 AI “git push --force 到 main，我这搞乱了”
- 门控拦截（CODE-018 修复后的行为：破坏性规则优先于琐碎跳过规则求值——git push --force 不会再被“git 是常用命令”放过）。
- 同时 CODE-006 不可逆操作无确认进报告：force push 前应确认远端无他人提交。
- 躲过：同事上午推的三个提交被静默覆盖，git reflog 考古两小时。

### 例 11：团队的日常使用形态
- UserPromptSubmit 值班：每次有人向 AI 提需求，自动附一份快扫预报告（⚡快扫，毫秒级）；
- 谁被 AI 坑了 → 提 issue → 5 Whys（坑卡缺口？流程缺口？披露缺陷？）→ 回写入卡 → 全团队下次自动扫到；
- 一个月后，这个团队的坑卡库比任何一个人的经验都厚——这就是复利。

## 五、做 AI agent 产品的人（抄架构，不是抄工具）

### 例 12：给自己的 agent 定“完成”的验收标准
- 抄走的：**完成 = 环境状态变化**（τ-bench 的设计核心——任务完成以数据库状态为证，不以 agent 自述为证）。
- 落地形态：验收脚本断言文件已生成且内容正确、数据库行已变更且值符合预期、外部系统已返回预期响应。
- 价值：把“agent 说做完了”从信任问题变成工程问题。

### 例 13：给 agent 的输出加诚实分区
- 抄走的：**三区契约**（✅已查证带证据链 / ❓未验证附原因 / 🚫盲区含未覆盖范围）+ **置信度三档**。
- 落地形态：agent 每次结论必须分区输出，未标置信度的陈述不得出现在已查证区；任何一区不允许空着不写。
- 价值：用户能抽查、敢抽查——抽查可行性本身就是质量担保；这也是对 sycophancy（谄媚）的结构性对抗。

### 例 14：内部验收从“演示通过”改成“连跑八次全对”
- 抄走的：**pass^k 一致性门**（单次 60% ≠ 八次全对 25%）。
- 落地形态：agent 产品的内部准出标准加入复跑比对；报告一致率而非单次 demo。
- 价值：避免把高方差系统当稳定系统上线——AI 代理的第一年，大量“demo 惊艳、生产拉稀”都栽在这。

### 例 15：给系统建“翻车登记簿”
- 抄走的：**元坑登记簿**（本方法论自己的 8 次翻车全部公开登记）+ **漏报可原谅、谎报不可原谅** 的判据。
- 落地形态：每次自伤（含被用户抓包的红队攻击）走 blameless 复盘，回写登记簿；追责看披露完整性，不看结果对错。
- 价值：把“系统会犯错”从遮羞布变成唯一诚实的成长路径——这一条比工具值钱，也是本项目自己四次实盘抓坑的制度来源。
