## 建议修改或保留争议的题目

### 1. Q07：不宜不加说明地强制唯一标签
“先写处理方案”允许两种合理推进方式：
- **ask**：先确认去重与保留规则，再给确定性方案。
- **default**：先写不涉及数据修改的条件式方案，把业务规则列为实施前置条件，而不是自行替用户决定。

因此，本草案选择 **ask**，但不应仅凭标签否定第二种回答。若要稳定单标签，可将任务改成“给出唯一、确定的去重和保留规则”，使缺失信息真正阻断当前交付。

### 2. Q08：建议补全导入信息
框架风格足够明确，但“只给测试代码”通常隐含代码可直接使用。题干没有说明函数来自哪里、如何导出。建议补充目标模块路径及导出声明，或明确现有测试文件包含这些信息。否则，**inspect 是合理的第一步，却不保证能完成交付**。

### 3. Q03、Q05、Q11，以及部分 Q08：需要明确 inspect 与 default 的边界
这些题已经摘录了所需依据。合格回答可能直接引用摘录并交付，不再发生新的读取动作。

因此，**inspect 应包含“依据已给材料作答”**。若将其限定为“必须新调用一次读取工具”，这些题就容易与 default 重叠，测到的是工具使用形式，而不是是否需要澄清。

### 4. Q04：宜单列时间窗口这一缺口
题干重点提到了按金额／订单数、按下单月／退款发生月，但“最近一个月”本身还有自然月与滚动时间窗口的歧义。评分不应忽略这一项，也不宜要求每种合理澄清都使用完全相同的问法。

**结论：没有题目必须直接排除。Q07 建议允许多种合格路径，Q08 建议补足材料；若无法修改且必须用于严格单标签评分，建议暂不将这两题计入。其余题目应先统一 inspect 包含“引用已给证据”的定义。**
