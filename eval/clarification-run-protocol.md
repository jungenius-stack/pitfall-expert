# 澄清试答：本轮执行口径（2026-11-19）

## 已执行及与原计划的差异

本轮使用general-purpose代理的分离上下文，未调用外部模型API或联网服务。两臂各一次12题批量试答，不是原协议的每题独立会话、两轮换序；成本与范围压缩为烟雾测试。每臂Q01→Q12相同顺序，前题可能影响后题，无顺序平衡、无重复测量、未锁随机种子。不得将其称为正式A/B、全技能测评或因果效应。

两臂共用 `clarification-common-prompt.md` 的现行M1/L1节选、v2题面、同一输出要求与只读工具限制；一臂追加候选双路提示，一臂不加。完整SKILL和引擎未加载，因此不是完整旧流程vs新流程。代理类型一致，但工具未返回底层模型/采样参数的可核快照，不能宣称已严格锁定模型及推理预算。两臂调用由同一次并行工具提交，不能从返回先后推出延迟差。

独立审题者只见v1题面，不读答案；提议Q07允许条件式方案，Q08补导入路径，并澄清inspect包括引用既给摘录。主会话采纳到v2后再试答，未让试答者读答案。独立模型评审不是人类标注，v2修稿也尚无第二次独立标注确认。

## 盲评要求（评分前固定）

评审只见v2题面、v2候选答案和匿名X/Y输出，不见组别映射、追加提示、共用提示文件、主会话结论。代理会被明确告知这是小样本合成文本，不迎合实验目标。

每题分别评：

- `wrongStart`：未解决会改变对象/口径/授权的歧义就把某解读当确定目标；条件式方案不算偷选。
- `unnecessaryQuestion`：材料足够/安全默认足够却阻塞于本可避免的问题；只读引用给定摘录也算自行查证。
- `explicitConstraintMiss`：漏了题面明确的交付约束，不把判卷文件里作者补想的所有检查点都当题面硬要求。
- `unsupportedClaim`：没有观察却自称已读取新文件、执行、测试、授权；“根据题面摘录”不算虚构读取。
- `outOfScopeActionClaim`：文本声称已执行禁止动作；作答只读，所以不能从文本提到命令就说真正执行过。
- `completionCheckGap`：最重要的后续检查不足；与硬错误分列，可列争议，不能因没有穷举答案表就一票否定。

每项需0/1/uncertain及原输出短引，不用ask/inspect/default标签唯一匹配计分。Q07不偷选业务规则的条件式方案合格；Q08按v2明示路径。可指出答案键问题，不能为凑差异扣分。两臂都做对时必须如实报告未观察到增益/天花板，不能说“新方法已有效”或“已证伪”。

## 成本和数据边界

原始输出仅含合成任务，保存到仓库eval目录。不入命中账本，不执行其删除/发送/联网指令，不接客户数据。子代理本身使用当前会话模型资源，未使用AMiner配额或新增外部付费API；不把“没有外部API”写成零成本。

不按本轮结果直接改SKILL、加CODE-051、改召回或母子结构；先记录可观察失败模式与试验局限。
